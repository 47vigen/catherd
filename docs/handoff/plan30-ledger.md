# Plan 30: the run daemon — ledger

Executed on branch p30-daemon (based on plan 29 at 2fb4a9d). Tasks 1-11 of docs/plans/2026-10-21-30-run-daemon.md.

Ruling: describeEvent takes an optional second argument `rungOf(dispatchId)` — the plan's test text names the rung of a `dispatch.ended`, but that event carries none and the signature has no state — `runTimeline` passes the state's table; without it the line ends before "on <rung>" — cost: a caller that forgets the argument shows no rung.
Ruling: `dispatch.started` gained an optional `judgeKind` — `judges` needs the kind to ask the same question again after `judge.failed`, and no other event names it — additive, absent on every other dispatch — cost: none for a consumer that ignores it.
Ruling: RunState gained `planDirty`, `waiting`, `stuck`; MilestoneState `awaiting`, `tries`, `delta`, `confirmed`; LaneState `climbReason` — the machine is level-triggered, so every pending decision (a park the owner must get, a refusal's wait, an unread plan, the reviewers a round still owes) has to live in the fold, not in an action nobody remembers — additive; plan 30b/31/35 read the contract's fields unchanged — cost: a consumer that builds a RunState by hand must give them.
Ruling: DispatchView.thread is the latest known thread (set again when the dispatch ends) — the reviewer's next round and a fix round resume it — cost: none.
Ruling: a verifier FAIL after a clean review is not "no progress" — D8's n_r ≥ n_{r-1} compares against a round that had findings (the clean 0 is no baseline); the soft cap still binds — otherwise the first FAIL after a clean review would park at once, against the table row "fixes and re-verifies on a FAIL" — cost: a FAIL/clean alternation runs to the soft cap.
Ruling: the judge follows the orchestration host on a Codex host (`codex:gpt-6.1-sol#medium`), like the architect and the verifier, and `hostDefaultsDoc` clears its stored rungs too — a Codex-only profile must not need the Claude CLI for a role it never asked for (doctor's Codex tests said so) — on every other host it is headless Opus medium as the plan says — cost: a Codex-host owner gets a Codex judge unless the profile names its rungs.
Ruling: the judge's `question` context is a pointer (`reply: roles/<name>/<id>/reply.md`) plus one line; `judgeBrief` (services) appends the reply's last 3000 characters — the machine is pure and events carry no reply body — cost: none.
Ruling: effect.failed names its action by `<type>@<unit>` (`failKey`), and `confirms(effect.failed)` returns that; the daemon frees any issued action whose `failKey` equals a confirmed key — `effect.failed` has no field for a dispatch's name — cost: none.
Ruling: the daemon's env is the launcher's minus catherd's own secrets (scrubSecrets) and CATHERD_ROLE, but keeping TYPESAFE_API_KEY (Jev routing) — tighter than "inherits the launching process's env": the Claude Code session identity and messaging token are the MCP server's alone — cost: none (the daemon has deps.session = null).
Ruling: admission accepts a rung's headless twin (`claude:` → `claude-code:`, `headlessRung`) on a role's ladder, so the daemon runs the profile's native Claude rungs headless without rewriting the profile — spec 2.0 decision 12 — cost: a ladder holding both forms is allowed twice, harmlessly.
Ruling: `plan.md` supplies each milestone's title (`## M<n> — title`, else the id) and its `After:`; a lane file `M<n>.L<k>.md` belongs to milestone M<n>; a milestone with a heading and no lane file is left out — an empty milestone would never route — cost: a plan with a heading and no lanes shows no such milestone.
Ruling: a verifier whose reply opens with no readable VERDICT line (markdown around it, text before it) and exited ok ends as `verdict: "fail"` with a finding naming the first line — `land` counts such a reply as no verdict, so a fix round beats a verifier that retries forever — cost: one spurious fix round for a verifier that wraps its verdict.
Ruling: a fix lane's finding file is the first `path` token among its first four words, so a verifier FAIL line like `bun test src/a fails` is routed to the lane owning `src/a` — helpful more often than not; an unowned one goes to the judge — cost: a path mentioned in passing may route a line to the wrong lane.
Ruling: the fast check's tail is `runCheck`'s own (the last 20 lines), not 40 as the plan says — the existing runner caps it, and widening it changes preflight's output too — cost: a lane's notes carry 20 lines.
Ruling: a quota's hold counts only while `until > state.at` when the effect picks a rung (`Object.keys(s.holds)` would also name expired ones until the next tick event) — cost: none.
Ruling: the daemon marks a finished dispatch's record read (`tryCollect` then `endCollect`) once `dispatch.ended` is appended — no session announces a 2.0 role's finish (Ruling 19), and an unread mark would list it in `peek` forever — cost: `peek` shows nothing for a daemon run's finished roles.
Ruling: `judge.failed` is not appended for a judge that ended on a limit — the hold and `judgeRetries` re-ask it, and counting it would park a unit on a quota, not on a bad answer — cost: none.
Ruling: the preflight of a lane whose check is `lock-busy` is not blocking — the lane's own fast check runs it again later — cost: a busy machine hides a broken check until the lane's check.
Ruling: the loop reads every new event before it looks at the clock, appends a `tick` only when no new event is waiting and `wakeAt` has passed, and beats every `beatMs` of its clock; an issued action's key is freed by `confirms(e)` or by an `effect.failed` carrying its `failKey`, and a `notify` key also when its effect settles (a notice leaves no event) — cost: none.
Ruling: `until` is checked at the top of each turn and leaves without waiting for in-flight effects (a test seam); the real daemon leaves only when the run has ended and no effect is in flight — cost: none.
Ruling: `postNotify` sends a non-ASCII title (the middle dot, a Persian run title) as an RFC 2047 encoded word, and races its fetch against its own timer — a raw non-Latin-1 header throws in `Headers`, and ntfy decodes the encoded word; a fetch that ignores its signal still gives up — cost: a client that does not decode RFC 2047 shows the word.
Ruling: `sendRunNotice` sends nothing under `CATHERD_NO_END_PUSH=1` (the test preload sets it) unless the caller passes its own `fetch` — the daemon tests finish runs through the real `notify` effect, and no test may reach ntfy.sh — cost: none; a real daemon never has it set.
Ruling: `startNotifier` polls the reports of the session's 2.0 runs only when `reportPollMs` is set (the MCP server sets 3 s), otherwise they ride `scan`, which every tool call and the boot trigger — the notifier's tests need no timers — cost: a session that never calls a tool hears a report within 3 s only through the poll.
Ruling: `runStart` is `startRun` (the check of the index, the pin, the claim) plus `run.started` and the daemon — one place makes a run, so a 2.0 run is a 1.5 run's folder with an events file — cost: state.md and the 1.5 protocol text are still written for a 2.0 run.
Ruling: `recoverOwned` and `adopt` skip a 2.0 run, as `reconcileAll` does (it only starts the daemon): a second watcher settling its limits would race the daemon's failover — cost: a 2.0 run whose daemon cannot start is not recovered by 1.5 paths.
Ruling: `summarizeRun` starts a dead 2.0 run's daemon (a failure is a warning in the summary) although its doc says reads are pure — the plan asks every reader to revive — cost: a status read can spawn a process.
Ruling: `profileTool` with `notifyUrl` sets the topic first, and `{ action: "set", notifyUrl }` with no patch returns `{ notifyUrl }` — one tool for profile and topic as the spec says — cost: none.
Ruling: `status` keeps `paused`, `host` and `queue` beside the plan's `{ version, runs, warnings }` — the machine pause comes first by the 1.5 spec's "Group pause", and the host and queue say why a Codex session hears nothing — additive; a client that ignores them loses nothing — cost: none.
Ruling: the full server no longer refuses `record_agent_run` or binds run-file and gate tools to a role's run (those tools left it); the role server (role-server.ts) keeps its own bound tools and tests — cost: none.
Ruling: the stdio integration test shrinks to the six tools, a status, a profile read and one structured refusal — its 1.5 scenarios (restart reconcile, push, concurrency over dispatch tools) drove tools that left the session; the notifier, reconcile and admission keep their own service tests — cost: no end-to-end stdio test of a daemon run (a real daemon needs a real model CLI).
