# catherd 2.0, plan 36: release 2.0 — beta, scorecard, latest — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship catherd 2.0.0. Cut a `1.x` maintenance line from the newest `v1.*` tag that publishes bug fixes without moving `latest` once 2.0 holds it; make the scorecard count a daemon run's interventions; collect every breaking change of plans 29–35 in MIGRATION.md "From 1.5 to 2.0"; correct the README, the skills and the contributor docs; publish 2.0 to the `beta` dist-tag; hand the owner the scorecard commands and wait; compare against the 1.5.0 baseline by the pass bar; and only on a pass and the owner's word, promote to `latest`.

**Architecture:** one code change (`interventionsOf` reads `events.jsonl` in a daemon run, `src/services/scorecard-metrics.ts` and the `Interventions` type in `src/domain/scorecard.ts`), two workflow edits that live on the `1.x` branch, docs, one changeset, then release operations. No other file under `src/` changes.

**Tech Stack:** Bun ≥ 1.4, TypeScript, Changesets, GitHub Actions, npm OIDC trusted publishing. No new dependency.

**Spec:** `docs/specs/2026-10-12-catherd-2.0-design.md`, "Release" and "Measurement" (binding). Inputs: plan 28 (`docs/plans/2026-10-21-28-run-scorecard.md`, its Produces and Cross-plan interfaces), plans 29, 30, 30b and 31–35 (their Goal, Rulings and docs tasks are the source of what changed), plan 27 (`docs/plans/2026-10-02-27-release.md`, the house release plan), CONTRIBUTING.md "Releases" and "Beta channel", `.github/workflows/release.yml`, `.github/workflows/ci.yml`.

**Pre-validation:** spiked npm's dist-tag rule (`semver.validRange` parses `v1` and `1.x` as ranges, so npm refuses them as tags; it returns null for `v1-latest`, `legacy` and `release-1`, which npm takes) and `bun run <script> -- --tag x` (the args land after the script's last command: `… && changeset publish --tag x`); plan 28's scorecard tests do not exist until plan 28 executes, so targeted tests only at execution; the full gate runs at execution.

## Review Focus

1. **A 1.x fix published after 2.0 is `latest`.** Expected: it goes to `v1-latest`, `latest` stays on 2.x, and `catherd-cli@1` resolves to it. Task 2, the dist-tag step.
2. **A daemon run with a judge-answered question, an owner-answered one and one still open.** Expected: parks 2, answers 2; a milestone park is not counted twice (its `questions.jsonl` row and its event). Task 3: "counts in a daemon run the owner's answers and the questions still open, not the judge's answers"; "reads questions.jsonl only in a 1.5 run".
3. **A scorecard session that started the run without its plan.** Expected: the run waits for `plan.approved{ by: "owner" }`, which counts as an intervention, and `compare` fails that task. Task 3: "adds an owner's cancel and an owner's plan approval, not a plan given as input".
4. **Main moved after the beta was cut.** Expected: no promotion while `src`, `plugin`, `catalog`, `package.json` or `bun.lock` differ between the beta's commit and `origin/main`. Task 12, Step 1.
5. **MIGRATION promises something the code does not do.** Expected: every bullet traced to a grep hit (Task 5, Step 2).
