## Decisions

- D1 — gate_run splits a check at its top-level `&&` and keeps one record per item — rejected: one record per whole command — a whole-command record cannot tell which suite failed, and a red baseline of one suite hid another's fresh failures (audit 1, 6).
- D2 — land knows the milestone's check from plan.md's `Check:` line (`milestoneCheck`), and falls back to the recorded commands' items when there is none — rejected: a new `MilestonePlan.check` state field — the plan text is already the verifier's source, and no event or state schema has to change.
- D3 — land requires a gates.jsonl pass on the landed head for every gate_check item of the milestone — rejected: trusting the verifier's verdict — audit 3: a verdict with a failed item landed.
- D4 — gate_pass requires `milestone` and a matching step of that milestone; no fallback to the base checkout — rejected: inferring the milestone — the fallback recorded passes on the wrong tree (audit 2).
- D5 — a red baseline blocks the land (in `missing`, naming the pre-existing lines); the owner waives it through the existing park and `catherd answer … accept` flow — rejected: an audit note — audit 5: a gate that failed on the base too counted as green.
- D6 — failing lines are normalised (role, run id, absolute paths, ports, tmp dirs) before any comparison, and only the display is capped at 60 — rejected: a fuzzy match — normalising is exact and testable.
- D7 — a plan.md milestone whose `After:` adds a milestone the owner's plan input (same `## M<n>`) or plan-approved.md did not have parks a "approval" question at plan time — rejected: refusing the plan — the owner may want the wider order (audit 9).
- D8 — a verifier is not dispatched again on the commit it already FAILed or found broken (`verifierFailedOn`) until the milestone's head changes or the owner answers; a check_broken verdict parks at once — rejected: a retry counter — the re-run on an unchanged HEAD and env cannot give a new answer (audit 12).
- D9 — a parked, unanswered question is re-notified after 30 min, 2 h, 6 h, 24 h, then every 24 h, through a `remind` action and a `question.reminded` event; it reuses the "blocked" notify moment — rejected: a new notify moment — no profile change (audit 24).
- D10 — a role run with no cost from its backend (Codex, Cursor) is priced in finalize from the catalog's list price of its rung (`tokensUsd`); when the rung has no catalog price the cost stays null — rejected: pricing in each adapter — finalize already has the run dir and the rung (audit 21).
- D11 — totals sum only priced runs and count the rest in `unpriced`; `costUsd` is null when no run is priced; the text reads `$X (+N unpriced)` — rejected: `?? 0` — a null summed as zero under-reports (audit 20).
- D12 — `Tokens.cacheWrite` is optional and filled by the claude-code, opencode and cursor folds; `input` keeps its meaning (all input), and the views show uncached = input − cached − cacheWrite — rejected: redefining `input` — old records and every reader would change (audit 21).
- D13 — a `check.ran` failure whose failing lines equal the previous one's on an unchanged lane head is an environment failure: the lane parks as check_broken and `climbReason` is not set — rejected: classifying by error text — identical output on an unchanged head is the signal the machine can trust (audit 22).
- D14 — `status --json` questions come from the replayed run state for a 2.0 run (as `parkedOf` does), and an ended run lists none — rejected: fixing the 1.x ledger — the daemon no longer writes it (audit 26).
- D15 — an ended run says so: the report opens with `Outcome: <finished|cancelled|…>` and what was left; `run.ended` and the finish notice use per-outcome text; land evidence and state.md never say "the daemon continues" once the run ended — rejected: one neutral "the run ended" text for every outcome — a cancelled run read as a finished one, and the owner could not tell what was left (audit 27).
- D16 — the ntfy title carries the park reason, the message the first 120 characters of the question (whitespace collapsed, code fences dropped) and the answer command; Click links the panel's questions page only when the panel recorded its origin; priority 4 for blocker, environment and land reasons — rejected: a configured public panel URL — that is a product decision, listed in ideas.md (audit 28). This overrides notify.ts's "never the question's text" docstring by the owner's acceptance line A1.
- D17 — panel numbers come from the server: Rounds from per-milestone review counts, Took shows "waiting on you X" from open questions, the step count shows done, skipped and failed, and Cost says "N unpriced" — rejected: computing them in the browser from the run graph — the panel's own count (`roundsOf`) already disagreed with catherd, and one source keeps the CLI and the panel equal (audit 29).
- D18 — run-state.ts, run-machine.ts and run-events.ts change only in M2; M4 reads the existing state and changes no reducer — rejected: an `After:` chain — milestones run side by side.
- D19 — the panel milestone (M5) runs after M3: it shows `cacheWrite` and `unpriced`, which M3 adds to the record and the totals — rejected: M5 in parallel, reading the new fields through casts — it would compile against a record shape that does not exist yet, and both milestones would regenerate web/openapi.json.

## Edge cases

- A check with no `&&` is one item; a `&&` inside quotes or inside parentheses (a subshell) does not split it.
- A plan milestone with no `Check:` line: machineGate requires every item of each command recorded for it.
- An item still running when gate_run returns: the call answers `running`; finished items are cached.
- A baseline record from before plan 39 (whole command, unnormalised lines): its command matches no item, so the item has no baseline and a failure blocks; the verifier reruns the baseline.
- A gates.jsonl pass with commit `head+uncommitted` never matches a landed head: refused.
- gate_pass from an old verifier with no milestone: E_INPUT_INVALID with a fix line, never a pass on the base.
- An owner plan with no plan-input files: only plan-approved.md is compared; with neither, no widened-dependency question.
- A question parked before plan 39 (no `reminded` in replay): treated as 0, reminded from its `at`.
- A reminder due while the daemon was down: one reminder on wake, not one per missed slot.
- Identical check failures after the lane committed a change: not an environment failure (the head changed).
- A Codex rung missing from the catalog: costUsd stays null and counts as unpriced.
- Old records without `cacheWrite`: read as 0.
- A question shorter than 120 chars: sent whole; newlines and code fences collapsed.
- No panel running: no Click header.
- A run cancelled before any milestone landed: headline names cancelled and every milestone as not landed.
