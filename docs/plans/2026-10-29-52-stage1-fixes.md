# Plan 52: stage-1 fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four faults eight real stage-1 scorecard runs (2026-10-28/29) exposed: the architect never climbs
on a quota limit, a gate that already fails on the base blocks the whole run, `CATHERD_LOCK_HELD` leaks into
catherd's own lock tests, and `catherd status` shows the deleted milestone machine's notes.

**Architecture:** The architect's ladder rides on `run.started` so the pure machine can pick a free rung (one helper,
`unheldRung`, shared with `delegate_task`). A failing full check runs the same command on the base itself (cached per
base commit) and records a verdict (`inherited | new | unknown`) in a new `checks.verdict` column; land and the MR
body read it. The status tail of an architect run reads the checks table instead of the 1.5 `state.md`.

**Tech Stack:** Bun ≥ 1.4, TypeScript, `bun:sqlite`, zod, `bun:test`.

**Spec:** `docs/specs/2026-10-27-architect-led-runs-design.md` (D6 checks, D7 rungs, D8 verifier, D10 caps, D11
landing).

**Pre-validated:** every task was built test-first in `.superpowers/plan52-scratch`; the scratch commits are on this
branch after this plan, one per task, in task order.

## Rulings

- **R1 — one ladder rule for the architect and for tasks.** The brief asked to reuse the delegated-task rule. There
  is none in the architect engine: a queued task on a held quota is refused `E_RUNG_HELD`, and the 2.0 stand-in
  failover (`dispatch-service.ts` `failover`, `failover-rungs.ts`) is not on the architect path. So the plan adds one
  pure helper, `unheldRung`, used by the architect's wake and by a no-rung `delegate_task`. Spec D7's "a quota limit
  does not climb" still holds for `ladderRung` (no step up for the work); `unheldRung` only skips a held quota.
- **R2 — the ladder is pinned on `run.started`** (`architectRungs`, headless, its default first), as `caps` is. The
  machine is pure and cannot read the profile. A run an earlier build started has none and keeps today's behaviour
  (it waits on its last rung).
- **R3 — the free rung is searched from the default.** With nothing held the architect returns to its default, on a
  fresh thread (a thread does not carry across backends; the "rung changed" note moves to the machine).
- **R4 — a quota-limit turn still counts as a failed turn.** Out of scope; in `ideas.md`.
- **R5 — inherited failures (owner brief, overrides spec D6's "baseline only on demand").** A full check that fails
  runs the same command on the base itself as check `<id>-base` (`fresh: false`, so it is reused per base commit by
  the existing `cachedRow`). Its verdict is `checkVerdict(exit, failures, base)`:
  `pass` on exit 0; `unknown` with no base result or on a timeout; `new` when the base passed; `unknown` when no
  failing line could be read (exit codes alone prove nothing); else `inherited` when every failing line is on the
  base, `new` otherwise. Failure identity is `checkFailLines`' normalized line, unchanged. A fast check never runs
  the base (it compares with a base row that exists, as today).
- **R6 — `inherited` counts as passing for land final and the verifier.** `greenFull` takes `exit = 0 OR verdict =
  'inherited'`; the inherited lines join Known issues as `inherited from the base (`<command>`): <line>`, and the
  proof line says `passed but for N failure(s) the base has too`. The verifier is told so in its prompt; it never
  reruns the full check. `new` and `unknown` block as today.
- **R7 — the lock leak.** On `main` the preload already deletes `CATHERD_LOCK_HELD` from `process.env`, and the whole
  suite passes with the variable set on the plan's machine. Removing that preload line reproduces exactly the
  real-run shape (lock-command tests fail). Bun's `Bun.spawn` without an `env` inherits the variable even after
  `delete process.env` (checked), so the preload is the one line holding it. The fix makes `lock-command.test.ts`
  drop it itself and adds a guard test that runs the lock tests with it set.
- **R8 — status reads the checks table for an architect run** (`isDaemonRun`): its `stateTail` is the one line
  `Last check: …`. `state.md` and its `FRESH` notes stay: they are the 1.5 orchestrator's.

## Review Focus

- **Every rung held, then one lapses** — the architect waits, then wakes on the free rung, not on its last one.
  (Task 1 test.)
- **A base that cannot be checked out** (no start commit) — the verdict is `unknown`, the check result still lands;
  `runArchitectCheck`'s base call is caught. Reviewer: confirm a throwing base never fails the outer check.
- **A full check that times out** — `exit: null` must never be `inherited`. (Task 4 domain test.)
- **A base run whose merge base moved** (land final merged origin) — the base check reruns on the new commit, since
  the cache key is the base sha. Reviewer: confirm `baseSha` is read per call.
- **An old run's events** (`run.started` without `architectRungs`, `check.done` without `verdict`) replay unchanged.
  (Existing machine tests run without the field.)
