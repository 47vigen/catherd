# Plan 54: the oracle rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce spec D9, the one mechanical gate: a writer may not change the oracle it is graded by without the
architect's say, and every other test edit is allowed and reported, including a test the run removed or rewrote.

**Architecture:** A ledger task already carries `oracle` paths (`src/domain/ledger.ts`, plan 47); nothing reads them.
`delegate_task` snapshots the tree for a worker or writer on a ledger task with an oracle (the plan 51 review
snapshot, reused). When that dispatch ends, the daemon diffs the oracle paths between the snapshot and the tree, writes
the diff to the run dir, and puts it on `dispatch.ended`; the machine marks the task HELD and wakes the architect.
The architect accepts with a new tool, `oracle_accept`, or sends the task back to restore it; `land final` refuses
while a held change is still in HEAD. Separately, the MR body and the verifier's brief get catherd's own list of
tests the run deleted, removed (a test case gone from a file), rewrote (an existing test file that lost lines) or
skipped.

**Tech Stack:** Bun ≥ 1.4, TypeScript, zod, `bun:test`, git.

**Spec:** `docs/specs/2026-10-27-architect-led-runs-design.md` — D9 (the oracle rule), with D2 (the ledger's `oracle`
field), D8 (the verifier), D11 (the MR body: "oracle overrides, and deleted or skipped tests"), O4, and Migration item
17 (stage 2: D5, D6, D9).

**Pre-validated:** both tasks were built test-first in `.superpowers/plan54-scratch` (from `main` d6437eb); their
commits follow this plan's commit on this branch, one per task, in task order. Full gate green on the final head.

## Rulings

- **R1 — D9 on the shared tree.** Stage 2 pairs D9 with per-writer trees (D5), which no plan has built yet; plan 53
  is D6 only. D9's "a merge … is held" has no merge on today's shared tree, so the hold point is the dispatch's end
  and the gate is `land final`. — Waiting for D5 would leave the oracle field dead for another plan, and the rule is
  small. — Cost if wrong: when D5 lands, the diff moves from "snapshot → tree at the dispatch's end" to the merge's
  diff; `oracleChange` is the one function that changes.
- **R2 — the diff is the task's window, not its author.** On the shared tree, any edit to the oracle while the task
  worked (another writer's, the architect's own) is in its diff. The digest names the diff file, so the architect
  sees it. Plan 45 dropped `testEdits` for the same reason (`writer-attribution.test.ts`); this differs because a
  hold is a question to the architect, never a failed attempt. — Cost if wrong: a false hold costs one
  `oracle_accept`. In `ideas.md`.
- **R3 — the base is the tree at delegation.** `delegate_task` takes the snapshot (the plan 51 `snapshotTree`, one
  `task.delegated.snapshot` field, no new event field) for a worker or writer whose `ledgerTask` has a non-empty
  oracle. The plan 51 consumers read the snapshot of reviewer tasks only (`lastReview`, `reviewLines`), so a worker
  carrying one changes nothing for them. — A dispatch-start snapshot would narrow the window by the queue wait but
  needs a field on `dispatch.started` and a git call in the start path. — Cost if wrong: a queued task's window
  includes edits made while it waited (R2's cost).
- **R4 — an oracle set after delegation covers the next attempt only.** That attempt had no snapshot. In `ideas.md`.
- **R5 — who is held: the task's worker or writer, never a reader.** Reviewer, verifier and researcher tasks never
  take an oracle diff (they do not write). The architect's own edits are not held (D9: "authored by that task's
  writer"); they are reported by R8.
- **R6 — release is "accepted, or not in HEAD".** `land final` lists each held task whose oracle paths still differ
  from its snapshot at HEAD (`git diff --quiet <snapshot> HEAD -- <paths>`). Restoring the files releases the hold
  without a tool call. A snapshot git cannot read (gc'd) keeps the hold until it is accepted: fail closed. Non-final
  land never checks it (a checkpoint push is not the product leaving the run).
- **R7 — `oracle_accept {taskId, why}` is a new architect tool,** not a field of `findings`: findings are review
  results, and an oracle hold is not one. Its event `oracle.accepted {taskId, by, why}` joins land's change-log
  events, and its `why` is the override's reason in the MR's new "Oracle overrides" section. Refused for a task that
  holds no change (none, or already accepted).
- **R8 — the stage-1 evidence belongs to D9's reported half.** In a real scorecard run the architect deleted an
  existing test that contradicted the plan. It was right to, but neither the MR body nor Known issues named the
  removed test. The MR body already listed deleted test *files* and added skips (plan 50), not a test removed from a
  file that stays. Fixed here: `removedTests` parses the run's `-U0` diff for test declarations
  (`it|test|describe(.x)("name"`, Go `func TestX(`, Python `def test_x(`) on `-` lines of test paths whose name no `+`
  line of the same file declares again (a moved or edited test is not removed). A "rewritten" test is reported per
  file: an existing (`--diff-filter=M`) test file that lost lines, with the count, unless it is already listed as
  having a removed test. Per-test rewrite detection needs a parser per language; in `ideas.md`.
- **R9 — the fact reaches the verifier mechanically.** `delegate_task {role: "verifier"}` appends catherd's record
  (R8's lines against the base, then accepted oracle overrides) to the brief the architect wrote. The architect's own
  brief stays first and unchanged. When nothing changed, no block is added. The verifier contract gets one step
  saying what to do with it (product, not process: a removal that lets a bug pass is a FAIL).
- **R10 — the MR section is renamed** "Tests deleted, removed, rewritten or skipped", and "Oracle overrides" goes
  before it. The `ideas.md` entry "The MR body has no oracle-overrides line" is removed.
- **R11 — no panel change.** The panel's timeline shows any event through `describeEvent`; the new event gets a case
  there.

## Review Focus

- **A dispatch that ends while git fails** (the tree gone, a lock): the oracle diff must never stop the
  `dispatch.ended` from being written. `settle` wraps `oracleChange` in `.catch(() => null)`; `oracleChange` returns
  null on a missing tree or a failed snapshot. Reviewer: confirm no throw path reaches `withEventsLock`.
- **A daemon restart that adopts a running dispatch** settles it again: the oracle diff is taken then, against the
  same `task.delegated` snapshot. Reviewer: confirm `adopt → settle` is the only path to `dispatch.ended` for a
  worker.
- **An oracle entry that is a directory or a glob** (`test/acceptance/`): git pathspecs take it as is, and the event
  lists the changed files under it. Reviewer: confirm no code compares oracle entries with paths as strings.
- **A held task that is retried**: the new attempt has its own snapshot (taken at its delegation, so it already holds
  the first attempt's edit). Its diff is empty when it leaves the oracle alone. The first attempt's hold is released
  only by a restore or an accept (R6). Test: Task 2's land test restores the file and the refusal drops the oracle
  line.
- **A verifier delegated on a run with no base and no start commit**: `testFacts` returns only accepted overrides,
  never throws. Reviewer: confirm the brief is still written.
