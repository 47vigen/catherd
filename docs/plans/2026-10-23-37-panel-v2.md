# catherd plan 37: the panel v2 — a dashboard, a live run graph, a complete Setup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** opening the panel shows at once what every run is doing: a dashboard across repos, a run page drawn as a live graph whose every node opens its prompt, log, output, diff and checks, a Setup that edits the whole profile with a before → after preview, hands-on Questions, plain explanations everywhere, and run control (cancel, pause/resume one run, cancel one role, answer).

**Architecture:** the server derives everything from the run's files: an in-memory run index (mtime-keyed) feeds the list and the dashboard; a pure domain fold (`src/domain/run-graph.ts`) turns a run's state, events and dispatch records into a run model (nodes, attempts, edges) and a patch per event; a per-adapter transcript parser turns a role's raw stream into transcript items. New zod operations in `src/entry/panel/openapi.ts` expose them; the run socket keeps its TimelineEntry frames and adds the model patch, plus a transcript channel per watched dispatch. Per-run pause is a `run.paused`/`run.resumed` event pair the machine honours. The web app renders the model with React Flow laid out by elkjs, a drawer per node, small SVG charts, bundled provider marks and a glossary.

**Tech Stack:** catherd: Bun ≥ 1.4, TypeScript, zod 4. Panel (`web/`): Vite 8, React 19, HeroUI v3 + `@heroui/styles`, Tailwind v4, TanStack Router and Query, `@hey-api/openapi-ts` 0.99.0, Geist, `@gravity-ui/icons`, shiki, `react-aria-components`, Vitest + jsdom, Playwright; new: `@xyflow/react` (12.12.0 at writing) and `elkjs` (0.12.0), latest at install.

**Spec:** `docs/specs/2026-10-23-panel-v2-design.md` (owner-approved; its "Decided by the owner" and "Calls made by the designer" bind). Builds on spec 2.0 decisions 23–26 and plan 31 (`docs/plans/2026-10-21-31-panel.md`, whose Rulings 3, 4, 6, 7, 10, 17, 19 and 23 still stand).

Written against `panel-v2` at 2edae7f (main 2d6c5eb). Not pre-built in a scratch copy; Tasks 4 and 8 name the two spikes that carry risk (hey-api over the new schemas, elkjs under the panel's CSP).

## Rulings

1. Ruling: per-run pause is a `run.paused { by: "owner" }` / `run.resumed { by: "owner" }` event pair; the reducer keeps `RunState.paused` (the time it started, null when not paused) and `next()` drops `dispatch` and `judge` actions while it is set, so live roles finish and nothing new starts; the machine is level-triggered, so the `run.resumed` event itself re-issues the held dispatches with no 5-minute refusal back-off — the spec asks for exactly this storage — cost if wrong: an admission-time check would also be needed for a dispatch started outside the daemon, which a 2.0 run does not have.
2. Ruling: `pauseSpans(run)` returns the machine's, the workspace's and the run's own paused spans, and `spendOf` subtracts them from the budget minutes. The spec says machine pauses "already are" left out of the minutes budget; in the code only the ledger minutes and the scorecard leave them out, so this also stops a machine pause from spending a run's minutes — a long machine pause no longer parks a run on `budget`.
3. Ruling: idle and wall timeouts need no change: they bound live dispatches, which keep running through a pause.
4. Ruling: the run list and the dashboard read the run index, which never revives a dead daemon; `getRun` (opening one run) still does — the index is a pure read — a dead daemon of a run nobody opens waits for `catherd status` or the run page.
5. Ruling: the run index keys each run by `mtimeMs:size` of `events.jsonl` and of `runs.jsonl` (`0:0` when missing); 1.5 runs keep `engine: "1.5"` (the spec's "1.x"; the existing `RunView` value) — `superseded` interventions, which depend on other runs, refresh only when the run's own files change.
6. Ruling: dashboard spend is bucketed by the run's start day (UTC), zero-filled per day of the range — no per-record day split — a run that spans midnight counts on one day.
7. Ruling: the transcript parser is an optional `transcript(line, n)` on `BackendAdapter`, implemented for codex and claude-code (and the `claude` native pseudo-backend reads as claude-code); opencode and cursor fall back to one `raw` item per line — the spec's "message extraction where known" — their raw toggle shows the same lines.
8. Ruling: role streams carry no per-line timestamps, so transcript tool cards show no duration (the spec's "duration" per tool call); the node's and the attempt's durations come from `runs.jsonl` `secs`.
9. Ruling (controller, overrides the writer): markdown (brief, reply, plan, report, docs) is RENDERED with `react-markdown` + `remark-gfm` (no `rehype-raw`: raw HTML from agents stays escaped), code fences highlighted through the existing shiki `CodeBlock`, inside a `Markdown` component in `web/src/components/markdown/` styled with Tailwind classes (no new CSS file), with a "Source" toggle that shows the raw text in `CodeBlock lang="markdown"` and a copy button. Readability for any user outweighs the dependency count; the spec's dependency line is amended accordingly.
10. Ruling: the setup probe cache is keyed by adapter id and `PATH`, TTL 60 s, stale-while-refreshing, plus "Re-check" (`force`) — adapters expose no binary path to key by mtime — a CLI installed while the panel runs shows up within 60 s or on Re-check.
11. Ruling: the socket keeps one connection per run (the shared `live-socket` is a singleton): an event frame is the existing `TimelineEntry` plus `kind: "event"`, `event` and `patch`, so today's client keeps working; the client sends `{"watch":"<dispatchId>","from":<line>}` (or `{"watch":null}`) and gets `{ kind: "transcript", dispatchId, items, raw, next }` frames.
12. Ruling: run docs are read with a query, `GET /api/runs/{id}/docs?name=lanes/M1.L1.md` — a path parameter cannot hold `/` — names match `RUN_DOC_NAME` only.
13. Ruling: a missing doc or log answers 404 through `E_RUN_NOT_FOUND` with a message naming the file — the server maps that code to 404 already — the code reads "run" for a file.
14. Ruling: the dispatch → node and question → node maps are the tables in Task 3; a milestone question whose reason has no node of its own goes to the node of the step it parked from (`parkedFrom`), else `route`; a run-level question goes to `architect` while planning or awaiting approval, else to `start` (titled "Run").
15. Ruling: the ladder editor saves the user's order through a profile patch (`roles.<role>.rungs`), with drag and drop plus "Move up"/"Move down" buttons as the keyboard path; `setRoleRungs` (which sorted by intelligence, plan 31 Ruling 12) and `orderRungs` are removed in Task 16 once no page calls them — the spec asks for drag to reorder — profile validation still warns on a ladder that does not rise.
16. Ruling: every Setup call takes `repo`: absent means the repo the panel was started in, `global` means the active profile (no repo); the host question (`setHost`) records the host through `recordHost` and swaps the server's deps to that host, as `daemonDeps` does — catherd never guesses — the panel process keeps that host until it stops.
17. Ruling: provider marks are re-copied from remora's `provider-icon` (Bifrost-derived, Apache-2.0: `anthropic`, `openai`, `opencode-go`), trimmed to those three, with the exact derived header and a THIRD_PARTY_NOTICES line (plan 31 Ruling 9: "a later page re-copies one"); cursor and any unknown backend get a one-letter monogram. "Claude", "Claude Code", "Codex", "OpenAI", "opencode" and "Cursor" are names of backends the user configured, and the brand rule `/remora|bifrost|maxim(?!um)|cliproxy/i` does not match them, so they may appear in code and copy.
18. Ruling: the changeset is `minor`: a user-visible feature; with 2.0.0's `major` changesets pending, the computed version stays 2.0.0 and the entry lands under "Minor Changes" — none.
19. Ruling: shared files have one owner per wave (Parallelism); a wave-2 page that needs a wave-2 sibling's component gets it wired in wave 3 (the Log tab shows raw lines until Task 15 plugs in Task 12's view).
20. Ruling: fixtures come from the real smoke run `20261022-192138-case-helpers` (one milestone, a fix round, a rules judge), sanitized with `sed -e 's#/Users/vigen#/home/user#g' -e 's#Users-vigen-agora-lab-catherd-smoke#home-user-smoke#g'`; a test asserts no `/Users/` string is left.
