# catherd 1.6, plan 28: role prompts, briefs and the reply contract — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every headless role (Codex, opencode, claude-code, …) gets the same role text a native Claude subagent carries, as labelled sections the server builds; the reviewer, worker (and its fix round), verifier and every role get the rules t3herd's runs taught; the reply contract gains `HEAD:`, `EXTRA:` and `REJECTED:` lines with domain parsers that later plans consume; a fix-round worker's brief carries its findings, the verifier's FAIL lines and every lane's fast check, and the fixer's `REJECTED:` lines reach the reviewer's re-check.

**Architecture:** `src/domain/role-prompts.ts` stops holding one string per role and holds its parts (role text, team text, done-when, reply contract); `roleSections(role, version, {context, task})` renders them as `<role>`, `<team>`, `<context>`, `<task>`, `<done_when>`, `<reply_contract>`, in that order. `rolePrompt` (the native agent file) is the sections without context and task; `composeBrief` (admission, headless only) wraps the orchestrator's brief, the lane file and the role notes as `<task>`. Native rungs never reach admission (`E_ADMIT_RUNG`, `src/services/admission.ts:180-183`), so a native agent never gets the text twice. The reply-line parsers live in `src/domain/record.ts` beside `parseReplyStatus`; finalize stores what they find on the record. The fix-round and rejected-findings notes are a new pure `src/domain/fix-brief.ts` plus a service `src/services/fix-brief.ts`, chained in admission after `verifierBrief`.

**Tech Stack:** Bun ≥ 1.4, TypeScript, zod 4. No new dependency.

**Spec:** `docs/specs/2026-10-12-catherd-1.6-design.md`, "Plan 28: role prompts, briefs and the reply contract"; t3herd at 71cbb6a (`/Users/vigen/agora/lab/t3herd`): `src/brief.ts`, `prompts/_brief.md`, `prompts/_team.md`, `prompts/_contract.md`, `prompts/role/{reviewer,fixer,worker,verifier,architect}.md`, `prompts/fix.md`, `src/step.ts:185-199` (`findingBlocks`, `failLinesOf`) and `:282-303` (`fixText`), commits bedff3b, 48ac945; its skill `plugin/skills/t3herd/SKILL.md:188-197` ("Commits and the MR").

## Global Constraints

- Layers `domain → infra → adapters → services → entry` (`test/architecture.test.ts`): `role-prompts.ts`, `brief.ts`, `record.ts`, `hints.ts` and the new `fix-brief.ts` are domain (no `node:fs`); `src/services/fix-brief.ts` reads the run and must not import `admission.ts` (admission imports it).
- The gate: `bun install --frozen-lockfile && bun run typecheck && bun run lint && bun run format:check && bun test`, run once on the combined head. Workers run only their task's test files.
- Commits: conventional, subject ≤ 100 characters, lower-case first word after the scope, no plan ids in the subject; check `git log` after each commit (a failed hook leaves the changes uncommitted).
- The reply lines, verbatim (this plan owns them; plans 29–33 consume them):
  - verifier: `HEAD: <the full sha>` on the line before the `STATUS:` line;
  - worker: `EXTRA: <path> — <why>`, one per file outside its lane it had to change;
  - worker in a fix round: `REJECTED: <the finding's first words> — <why>`, one per finding it rejects.
  - The separator is `—`, `–` or `-` with whitespace on both sides, as `STATUS:` already accepts.
- Section order, fixed: `role`, `team`, `context`, `task`, `done_when`, `reply_contract`; a section with no text is left out.
- Owner-ruling defaults (spec, "Owner rulings needed"): fix rounds after convergence (`roundCall`) are not ported; the architect's "more small lanes beat one long one" stays untouched.

## Review Focus

1. **A failover stand-in reruns an already composed brief.** Expected: one `<role>`, one `<task>`, one lane file, one notes block, one fix section; the lane file as it stands now. Pinned in Task 3: "writes each section once when a failover stand-in reruns an earlier brief" (the existing failover test in `test/services/failover-cancel.test.ts:205` also pins it).
2. **Reply lines written loosely**: a `- ` bullet, backticks, an en dash or `-`, a hyphenated path, no why, a short sha, `HEAD: main`. Expected: parsed as in Task 1's cases; a non-hex `HEAD:` is no head. Pinned in Task 1: "reads EXTRA:, REJECTED: and HEAD: lines as loosely as STATUS".
3. **A finding that names a file no lane owns, or no file at all.** Expected: it goes only to the milestone's first lane, marked "confirm it before you change anything"; never to every lane (they would edit in parallel). Pinned in Task 4: "routes each finding to the lane that owns its file, and an unowned one to the first lane only, marked".
4. **A lane re-dispatched outside a fix round** (a climb before the review; after the fix ended ok and the verifier passed). Expected: no fix section. Pinned in Task 4: "adds no fix section before the review or once the milestone is green".
5. **A worker that declared its out-of-lane file.** Expected: the hint is `extra: <path> — <why>` for that file, `violation:` only for undeclared ones. Pinned in Task 1: "hints extra for a declared violation, violation for the rest".
