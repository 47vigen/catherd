## Global Constraints

- Layers `domain → infra → adapters → services → entry` (`test/architecture.test.ts`); `web/` imports nothing from
  `src/`; `web/src/conventions.test.ts` stays the rule (no inline `style={}`, English copy, HeroUI v3 only).
- Every task writes its test first and sees it fail on the base, then makes it pass. Tests never touch the network or
  a real vendor CLI; tests delete `ANTHROPIC_API_KEY` (in-process) or pass `ANTHROPIC_API_KEY: ""` (spawned); every
  spawned process gets an explicit `env`; no wall-clock sleep decides a test (inject the clock or the wait).
- Store writes stay atomic, locked and schema-versioned; a file written by an older catherd still reads (Tasks 89,
  91).
- ProfileService stays the single writer of profiles.
- No personal infrastructure in code, docs or fixtures: no home-directory paths, no private host or server names.
- Root gate: `bun install --frozen-lockfile && bun run typecheck && bun run lint && bun run format:check && bun test`
  (run the full suite through `catherd lock --`). Web gate (in `web/`): `bun install --frozen-lockfile && bun run
  typecheck && bun run lint && bun run format:check && bun run test`; e2e: `bun run build && bun run e2e`. After an API
  schema change: `bun run panel:openapi`, then `cd web && bun run gen`.
- Commits: conventional, subject ≤ 100 characters, lower-case first word after the scope, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; check `git log` after each (a failed hook leaves the
  changes uncommitted).
- A milestone modifies only the files its **Owns** line lists. A file it must touch beyond that is a conflict: stop
  and report it instead of editing.
