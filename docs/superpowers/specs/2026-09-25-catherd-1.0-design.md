# catherd 1.0 — design

Date: 2026-09-25. Status: approved 2026-09-25 (all sections and the Jev and TUI amendments).
Supersedes, where they disagree: `docs/specs/2026-09-24-catherd-design.md` (the 0.x design) and
`docs/plans/OVERRIDES.md`. Everything in the 0.x design that this document does not change still holds
(roles, the orchestrator sequence in §10 of the 0.x spec, the climb rules, the reply contract).

Research behind every decision here: `docs/research/2026-09-25-*.md` (audit, opencode, Cursor/Grok,
models, TUI, Jev, and the opencode TUI study).

## 1. Why 1.0

The 0.x MVP ran real projects end to end and proved the idea: Claude orchestrates from the user's own
session, vendor CLIs do the work, Jev picks the rung, a ladder climbs on failure. It is not yet
reliable, and it is hard to extend:

- **opencode does not work.** catherd's install hint installs opencode v1 while the code targets v2;
  on v2 it still runs in the wrong directory, aborts workers on the first permission ask, never times
  out a hung run, records zero tokens, never classifies a quota error as `limit`, and treats all 7,056
  models.dev models as opencode models.
- **The run engine has races.** Dispatch admission is not atomic, reads write (duplicate RunRecords in
  10/10 trials of concurrent reconcile), a reused pid pins a role as running forever, failover on a fix
  round crashes, one corrupt file stops the MCP server, and nothing is written atomically.
- **The TUI is untrustworthy.** Enter saves and activates, Esc does nothing, `q` quits from anywhere,
  Ctrl-C discards work silently, Space deletes, 6 of 17 rows fit at 80×24.
- **The catalog is stale and partly wrong.** Only Sol, Luna and Opus 5.5 exist; Astra, Fable, Sonnet,
  Haiku are missing; efforts, context sizes and several seed scores are wrong or unsourced.
- **Adding a backend touches ~12 files**, and there is no schema version anywhere.

## 2. Goals and decisions

Audience: the owner and their team first, built to the standard of a public open-source tool (smooth
onboarding, `doctor`, documentation, stable interfaces). Team/enterprise features (shared profiles,
policy, audit log, Windows) are out of scope.

| # | Decision |
|---|---|
| D1 | Jev is **optional, recommended**. Without a key: the lane file's declared kind/difficulty, else the profile default. |
| D2 | **Clean break.** 1.0 is a new major; `init` rebuilds everything; no 0.2 migration code. Every file carries a schema version from 1.0 on. |
| D3 | Claude runs **both** as native Claude Code subagents (default for conversational roles) and as a new headless **`claude-code`** backend (`claude -p`). |
| D4 | TUI: **professional with a light identity**, opencode's TUI as the primary reference. |
| D5 | Phased release: **1.0** = foundation, Codex, claude-code, opencode (Go/Zen), discovery catalog, TUI, CLI, `doctor`, hardening. **1.1** = Cursor. **1.2** = Grok. The adapter interface covers all five from day one. |
| D6 | Stay on **Bun ≥ 1.4**; lazy imports, runtime version guard, CI matrix. Standalone binaries later. |
| D7 | Live verification runs on the owner's machine (OpenCode Go, Claude plan, Codex with ChatGPT login) through a fixture-capture kit; CI runs on simulators and recorded fixtures. |
| D8 | Parallel lanes keep the **shared working tree**, with atomic admission, path-aware overlap and out-of-lane write detection. Worktrees are a later idea. |
| D9 | Rewrite strategy: **new architecture in place, porting proven parts** (routing, Jev client, Codex event parser, reply parser, role prompts, the orchestrator skill's sequence). |
| D10 | Per profile, per role **access mode** (`read-only` / `workspace-write` / `full`), with the backend's enforcement level shown. |

Non-goals for 1.0: Windows, a web dashboard, headless orchestration, worktrees/race mode, automatic
catalog tuning, standalone binaries, team features.

## 3. Architecture

### 3.1 Layers

```
src/
  entry/     cli.ts (citty, lazy subcommands) · mcp/ (MCP tools) · tui/ (OpenTUI)
  services/  run-service · profile-service · catalog-service · doctor · report
  domain/    types · schemas (zod, versioned) · routing (select, route, jev) · errors
  adapters/  backend.ts (interface) · codex/ · claude-code/ · opencode/ · cursor/ · grok/
  infra/     store (atomic write, JSONL, file lock) · supervisor · heavy-lock · log · paths · proc
```

- The dependency order, lowest first, is `domain` (pure types, schemas, errors, routing; no I/O) →
  `infra` → `adapters` → `services` → `entry`. A layer imports only from layers below it, and never from
  the 0.x modules (`src/core`, `src/mcp`, `src/routing`, `src/profile`, `src/tui`, `src/types.ts`), which
  are deleted once 1.0 replaces them. `test/architecture.test.ts` parses imports and enforces both rules.
- The entry layer (MCP tools, CLI commands, TUI effects) validates input, calls one service and
  formats the output. No business logic lives there.
- `cli.ts` imports subcommands lazily: `mcp`, `lock` and `_supervise` never load OpenTUI or React.
- A runtime guard at startup checks `Bun.version >= 1.4.0` and exits 1 with the upgrade command.

### 3.2 The backend adapter

```ts
type BackendId = "codex" | "claude-code" | "opencode" | "cursor" | "grok";
type Access = "read-only" | "workspace-write" | "full";

interface BackendAdapter {
  id: BackendId;
  minVersion: string;
  probe(): Promise<Probe>;              // installed, version, loggedIn, fix command per failure
  listModels(): Promise<DiscoveredModel[]>;
  plan(req: RunRequest): SpawnPlan;     // argv, env, cwd, PWD, prompt via stdin|file, isolation
  parse(line: string): EventDelta;      // incremental: thread, tokens, cost, lastEvent, retrying
  finalize(ctx: FinishedRun): Outcome;  // status, reply, tokens, costUsd, thread, images, error
  enforcement: Record<Access, "enforced" | "advisory">;
  errors: { limit: RegExp[]; tooOld: RegExp[] };
  resume: { supported: boolean; sameAccessOnly?: boolean; threadPattern: RegExp };
  interrupt?(thread: string, cwd: string): Promise<void>;   // server-side stop (opencode)
  graceAfterFinalMs?: number;           // kill if the CLI does not exit after its final event
}
```

A backend is one folder under `src/adapters/<id>/` plus its fixtures. No other module names a backend.
`RunRecord.backend`, `Profile.harness` and every switch derive from a registry of adapters.

### 3.3 Process model

Every worker runs under a detached supervisor entry, `src/entry/supervise-bin.ts <spec.json>`: a thin Bun
entry that never loads the TUI (`catherd _supervise <spec.json>` runs the same code, for manual use). It:

- starts the CLI in its own process group with stdin/stdout/stderr on files;
- writes `proc.json` `{ pid, pgid, startTime }` (start time from `/proc/<pid>/stat` or `ps -o lstart`),
  so a reused pid is never mistaken for the worker;
- enforces the idle and wall timeouts (idle asks the adapter whether the run is busy first) and
  escalates SIGTERM → SIGKILL after 10 s, calling `adapter.interrupt` first when present;
- writes `exit.json` `{ code, signal, endedAt, reason: "exited"|"idle-timeout"|"wall-timeout"|"cancelled" }`
  atomically when the worker ends.

A run is finished when `exit.json` exists, or when its supervisor is dead and its worker pid/start-time
pair no longer matches a live process. Exactly one process finalizes it: finalization first takes
`claim` with an exclusive create; a second finalizer sees the claim and returns the existing record.

### 3.4 Store

- Every JSON write is `write tmp → fsync → rename`. JSONL appends write one full line per `write` call.
- JSONL readers skip a corrupt line with a logged warning; a corrupt `meta.json` excludes that run from
  listings with a warning and never stops the server.
- A cross-process advisory lock (`<file>.lock`, exclusive create holding `{pid, startTime}`, stale when
  the holder is dead) guards read-modify-write of: a run's admission state, profiles, `config.json`,
  `projects.json`, the catalog override, and the agent links.
- Reads are pure: `status`, `watch`, `summarize` never finalize or write.
- Every file carries `"schema": 1` (JSON) or a header row (JSONL: first line `{"schema":1,"kind":…}`).
  Readers reject a newer schema with `E_CONFIG_NEWER_SCHEMA` and a "upgrade catherd" fix; unknown
  fields are preserved on rewrite.

### 3.5 Data layout

```
<config> = $CATHERD_HOME/config | $XDG_CONFIG_HOME/catherd | ~/.config/catherd
  config.json            { schema, activeProfile }
  projects.json          { schema, bindings: { <git toplevel>: <profile> } }
  profiles/<name>.json   §7
  catalog.override.json  treat-like, score and bar overrides
  credentials.json       { schema, typesafeApiKey } mode 600 (optional)
  agents/<profile>/…     generated Claude agent files
<data> = $CATHERD_HOME/data | $XDG_DATA_HOME/catherd | ~/.local/share/catherd
  discovery/<backend>.json   last listModels() of the home listing, with fetchedAt
  discovery/repos/<backend>-<sha16>.json   the same for one repo (sha16: first 16 hex of the
                             toplevel's sha256), for a backend whose models depend on where it runs
  logs/catherd-<date>.jsonl  7-day rotation
  locks/                     heavy-command slots
  repos/<slug>-<hash8>/knowledge.md
  repos/<slug>-<hash8>/runs/<run-id>/   §4.1
```

The repo slug gains an 8-char hash of the git toplevel path, so `/a-b/c` and `/a/b-c` never collide.

## 4. The run lifecycle

### 4.1 Run folder

```
meta.json    { schema, id, repo (git toplevel), title, aLines, createdAt, catherdVersion }
plan.md  lanes/Mx.Ly.md  ledger.md  state.md  state.json
runs.jsonl   RunRecord per finished role run (schema header row)
routes.jsonl route + climb decisions
outcomes.jsonl one row per lane when its milestone lands or it fails its top rung (§5.6)
jev.jsonl    every Jev call
agents.jsonl native Claude subagent runs reported by the orchestrator
roles/<name>/<dispatchId>/{brief.md, spec.json, proc.json, events.jsonl, stderr, reply.md, exit.json, claim}
shots/
```

Each dispatch gets its own folder, so rounds never rename files. `roles/<name>/latest` is a symlink
(or pointer file) to the newest dispatch.

### 4.2 Lane files

The architect writes a header of four required lines:

```
# M1.L2 — <title>
Owns: src/foo/, src/bar.ts
Fast check: bun test test/foo.test.ts
Kind: repo_code            (repo_code | terminal | ui | prose | research)
Difficulty: build          (copy | build | logic | hard)
```

`Owns:` paths are repo-relative, literal (never globs), and a trailing `/` marks a directory.

### 4.3 RunRecord

```ts
interface RunRecord {
  schema: 1; runId: string; dispatchId: string; name: string; role: Role; lane: string | null;
  backend: BackendId; rung: RungId; attempt: number; failoverFrom: RungId | null;
  thread: string | null; status: "ok"|"failed"|"limit"|"cli-too-old"|"timeout"|"cancelled";
  startedAt: string; endedAt: string; secs: number;
  exitCode: number | null; signal: string | null; cliVersion: string | null;
  tokens: { input: number; cached: number; output: number }; costUsd: number | null;
  changedOwned: string[]; violations: string[];      // changed files outside the lane's Owns
  replyStatus: "complete"|"partial"|"blocked"|"refused"|null; replyWhy: string | null;
  threadHeavy: boolean; access: Access; isolated: boolean; images: string[];
  error: { code: string; message: string } | null; replyPath: string;
}
```

Tokens follow one convention for every backend: `input` includes `cached`.

### 4.4 Dispatch

1. **Admission**, holding the run's admission lock:
   - the rung is in the role's ladder in the active profile (`E_ADMIT_RUNG`), and its backend is ready
     per the last probe;
   - `thread` matches the adapter's `threadPattern`; `name` and `lane` match the id pattern;
   - finished dispatches without a record are finalized first (as reconcile does); a dispatch then blocks
     until its record is written, not only while it runs;
   - no unrecorded dispatch has the same `name` (`E_ADMIT_DUPLICATE`);
   - the lane's owned paths do not overlap any unrecorded dispatch's, where a directory covers everything
     under it (`E_ADMIT_OVERLAP`);
   - the budget allows it (§4.6);
   - then the dispatch folder and `spec.json` are written and the lock is released.
2. **Run.** The supervisor starts the adapter's `SpawnPlan`. The brief always travels by stdin or file,
   never argv; positionals follow `--`. The worker env drops `TYPESAFE_API_KEY`, `CATHERD_*` secrets and
   any `*_API_KEY` catherd itself set, but keeps the user's own backend credentials. Progress
   notifications go out every 30 s inside `try/catch`.
3. **Finalize.** The adapter's `finalize` classifies the status; catherd computes `changedOwned` and
   `violations` (a diff of `git status --porcelain` before and after, minus other live lanes' paths),
   writes the record, and returns `{ record, hints }`. Hints: `climb: refused|blocked|unchanged`,
   `violation: <paths>`, `thread-heavy`, `limit`, `cli-too-old`, `failed: read <path>`.

Timeouts come from the profile: `idleMin` (default 15: no event, and the adapter reports not busy) and
`wallMin` (default 90).

### 4.5 Climb and failover

Climb rules are those of the 0.x spec §6.4, unchanged. `climb` records the reason and returns the next
rung (a fresh thread) or `top: true`.

On `limit`:
- the stand-in is `profile.failover[rung]`, else the adapter's default (opencode Go `X` → Zen `X` when
  Zen lists it), else none;
- the stand-in always runs on a **fresh thread**; for a fix round its brief is the lane file plus the
  fix brief, both passed by path;
- the stand-in goes through admission again, including the budget;
- with no stand-in, `dispatch` writes `Next: paused: <backend> usage limit` and returns hint `limit`.

### 4.6 Budget

`profile.budget: { minutes?, tokens?, usd? }`.

- **minutes** is wall-clock time since `run_start`.
- **tokens** and **usd** sum every RunRecord (all backends, including `claude-code`) plus
  `agents.jsonl`, which the orchestrator fills through `record_agent_run` from the usage the Agent tool
  reports for native subagents.
- At ≥ 80 %, `route` starts at the cheapest rung that clears the bar. At ≥ 100 %, admission refuses new
  roles (`E_RUN_BUDGET`); roles already running finish. The docs call this a soft cap.

### 4.7 Other tools

- `cancel(run, name)` stops a live dispatch (interrupt → SIGTERM → SIGKILL) and records `cancelled`.
- `preflight(run)` runs each lane's fast check once on the base tree behind the heavy lock, with a
  120 s timeout per check and a secret-stripped env. Results are `pass`, `fails-as-expected` (non-zero
  exit after the command started), `skipped` (checks a file the lane creates), or `cannot-start` (exit
  126/127, command not found, timeout). Only `cannot-start` blocks. With `profile.preflight.confirm`
  (default false) the tool returns the commands for the orchestrator to show the user first.
- `land(run, …)` writes the full five-column ledger row, computing minutes since the previous landing or
  run start, and appends `learned` to the repo's `knowledge.md` (keyed by git toplevel).
- On MCP server start: scan runs, reconcile with `exit.json`/`proc.json`, skip corrupt runs with a warning.

### 4.8 MCP tools (1.0)

`run_start`, `route`, `preflight`, `dispatch`, `cancel`, `climb`, `ask`, `land`, `read_knowledge`,
`write_run_file`, `read_run_file`, `result`, `status`, `set_next`, `record_agent_run`, `runs_summary`,
`catalog_query`, `profile_get`, `profile_validate`, `profile_set` (now including `failover`, `budget`,
`timeouts`, `access`, `jev`, `billing`). Errors return `{ code, message, fix }` as structured tool errors.

The plugin's `.mcp.json` pins `catherd-cli@<exact version>`; the MCP server reports its version and the
skill checks it in its first `status` call.

## 5. Catalog and routing

### 5.1 Rungs

A rung names its backend: `<backend>:<model>#<effort>`.

```
codex:gpt-6-sol#high     claude:claude-opus-5-5#high      (native subagent)
claude-code:claude-sonnet-5#high  (headless)     opencode:opencode-go/kimi-k3#default
```

`claude` is the native-subagent pseudo-backend (no process; `route` returns the agent name). Effort
`default` means "no effort flag".

### 5.2 Three data layers

1. **`catalog/models.json`** (shipped, versioned). Known model families: canonical id, per-backend ids
   (e.g. `gpt-6-sol` in Codex, `opencode/gpt-6-sol` in Zen), efforts per backend, context per backend
   (Codex 272K default), capabilities (tool use, image in, reasoning), notes (`ultra` = parallel
   subagents), and backend capabilities (Codex image tool requires ChatGPT login). 1.0 seeds: Claude
   Fable 5.1, Opus 5.5, Sonnet 5, Haiku 4.5 (no effort); Codex GPT-6 Astra, Sol, Luna and the listed
   GPT-5.6 models.
2. **Discovery** from `adapter.listModels()`, cached per repo at
   `<data>/discovery/repos/<backend>-<sha16>.json` (keyed by the repo) when listed for one, while
   `<data>/discovery/<backend>.json` holds the home listing: Codex
   `codex debug models`; opencode `auth list` + model list, limited to `opencode-go/*` and `opencode/*`
   (other providers opt-in per profile); Claude from the shipped list, refreshed from `/v1/models` when an
   Anthropic API key is present. Refreshed by `init`, `doctor`, `catalog refresh`, and at most daily on
   `route`. The 1.4 MB models.dev snapshot is removed.
3. **`catalog/scores.json`**: one record per canonical `model#effort` × dimension:
   `{ dim, value, benchmark, version, url, date, confidence: "verified"|"secondary"|"inferred" }`.
   Dimensions: `repo_code` (DeepSWE v1.1 / SWE-bench Pro), `terminal` (Terminal-Bench 4.0), `honesty`
   (broken-tool disclosure). Values that could not be sourced are replaced or marked `inferred`.
   **Bars are re-derived on the new benchmarks so the default profile still yields the approved ladder**
   (Track A `luna#high → sol#medium → sol#high → sol#xhigh`, Track B `sol#medium → sol#high → sol#xhigh`),
   pinned by a test.

`secs_per_task` is not hand-written: it is the median `secs` per canonical rung and kind over the
user's own runs, used for `objective: "speed"` once a rung has ≥ 5 samples; below that, rungs order by
effort within a model.

A discovered model with no scores is listed and **disabled** until the user maps it with "treat like".
Shipped data may carry default treat-likes, marked `inferred` and shown as such.

### 5.3 Cost rank

Computed per rung from the profile's `billing` per backend:

- `chatgpt-plan`: share of the 5-hour allowance, official weights (Luna 1, Sol ≈ 20, Astra ≈ 60) ×
  an effort factor; `ultra` and fast mode multiply.
- `claude-plan`: API price ratios as a proxy; Fable on Pro counts as metered.
- `subscription` (opencode Go): share of the monthly dollar limit.
- `metered` (Zen, API keys): estimated dollars per task from token prices.

Order: every subscription rung before any metered rung, then by the computed value.

### 5.4 Routing

Kind and difficulty come from, in order: Jev (§5.5 decision rule), else the lane file's
`Kind:`/`Difficulty:` lines, else the profile default rung. The selection and ladder algorithm of 0.x
(`select`, the speed-ladder rule) is ported unchanged. `routes.jsonl` records the source
(`jev | lane | default`); `outcomes.jsonl` records each lane's outcome (§5.6).

`ultra` rungs are never in a default ladder; the user enables them explicitly.

### 5.5 Jev

Facts that shape the design (`docs/research/2026-09-25-jev.md`): the API has three question types —
`choice`, `score` (2–10 ordered levels) and `noul` (yes/no, returns P(yes)); `confidence` is only the
rescaled top probability, `(n·p_max − 1)/(n − 1)`, so one threshold means different things for
different option counts; answers repeat ~91 % of the time; there is no calibration or feedback
endpoint; TypeSafe paused new sign-ups on 2026-09-22.

- **Optional.** `profile.jev.use: "auto" | "off"`; auto uses Jev when a key exists. `init` offers it,
  never requires it. Keys come from `TYPESAFE_API_KEY` or `credentials.json`.
- **Question set `route-v2`**, one call per lane, stored as versioned data with a content hash:
  - `kind` — `choice`: repo_code, terminal, ui, prose, research, other;
  - `difficulty` — `score`, four levels written as situations (copy a pattern / extend a pattern /
    new logic with invariants / unclear cause or open design);
  - atomic `noul` questions logged for calibration: `names_pattern`, `mechanical`, `shared_state`,
    `unclear_cause`, `open_design`, `cross_boundary`, `outside_repo`.
  Counts and facts (owned-file count, fast-check presence, extensions) are computed in code, never asked.
  Computing them is deferred to `catherd jev eval` (1.x); 1.0 does not compute or log them.
- **State** is structured and trimmed: `{ title, owns, fast_check, body }`, with code blocks removed and
  secrets scrubbed; the state is never logged, only its hash.
- **Decision rule.** The kind is used when `p_max(kind) ≥ 0.8`. The track is decided on summed
  probabilities: Track A (copy/build work) when `P(A) ≥ 0.8`, Track B when `P(B) ≥ 0.8`, otherwise the
  lane file's declaration, else the default. Thresholds live in the data file; once ≥ 40 outcomes
  exist, `catherd jev eval` can suggest the cost-optimal threshold `p > c_Af / (c_B − c_A + c_Af)`.
- **Transport.** Thin client kept (the official SDK is 0.x and Node-targeted); 10 s per attempt, two
  retries with jitter honouring `Retry-After`, 25 s hard deadline; a per-run cache by content hash; the
  log row records the returned model, usage, `x-typesafe-request-id` and the question-set hash.
- `finding` and `same-defect` stay as in 0.x, with thresholds converted to probability terms
  (`finding` p ≥ 0.83, `same-defect` p ≥ 0.85, matching today's behaviour).

### 5.6 Calibration data

`outcomes.jsonl` per run, one row per lane when it lands or ends open:
`{ lane, questionSet, jevProbs, source, startRung, finalRung, climbs: [{from, to, reason}],
start_ok, min_ok_index, envCaused }`. Climbs caused by the environment (a missing service, a limit)
are marked and excluded from calibration. A lane written again (landed after ending open, or re-landed)
appends a newer row; the last row per lane wins. `catherd jev eval` (1.x, not 1.0) replays these outcomes and
reports Brier score, log loss, 3–5-bin reliability with Wilson intervals and flip rate across repeats.
Optional ε-exploration is out of scope for 1.0.

## 6. Backends

Common to all adapters: brief on stdin (or a file where the CLI cannot read stdin), `cwd` and `PWD`
set to the repo, a probe with minimum version, one token convention, a grace kill after the final event.

### 6.1 Codex (1.0)

- `codex exec [--ignore-user-config] -m <model> -c model_reasoning_effort=<e> --json -o <reply> -s <sandbox> -- -`;
  resume `codex exec resume … -c sandbox_mode=<sandbox> -- <thread> -`.
- Access → sandbox: `read-only` → `read-only`, `workspace-write` → `workspace-write`,
  `full` → `danger-full-access`. Enforcement: enforced.
- Discovery `codex debug models` (`--bundled` fallback). Efforts low…max and `ultra` where listed.
- Images from `${CODEX_HOME}/generated_images/<thread>/`.
- Isolation: catherd-owned `CODEX_HOME` with a symlink to the user's `auth.json`, plus
  `--ignore-user-config`.
- `failed` only from `turn.failed` or a non-zero exit with no reply; reconnect events never fail a run.

### 6.2 claude-code (1.0)

- `claude -p --output-format stream-json --verbose --model <full id> --effort <e>` with the brief on
  stdin; resume `--resume <session>`.
- Access via `--permission-mode` and `--allowedTools`/`--disallowedTools` matching the role prompts
  (`read-only`: no Edit/Write and no Bash, reading via Read/Grep/Glob; `workspace-write`: edits inside
  the repo; `full`: `bypassPermissions`). Enforcement: advisory.
- Tokens and cost from the final `result` event. Full model ids always, never aliases.
- Isolation: `--bare`-style minimal config (exact flag verified against `claude --help` when built).
- The native path remains: `route` returns `backend: "claude"` and an agent name; the profile chooses
  per role. Defaults: architect and verifier native.

### 6.3 opencode (1.0, v2 only)

- `probe()` requires v2 (`@opencode/cli` ≥ 2.0.16). v1 → `cli-too-old` with
  `curl -fsSL https://opencode.ai/v2/install | bash`.
- `opencode run --format json --auto --agent catherd-<ro|worker|full> -m <provider/model[#variant]>`,
  brief on stdin, `PWD`=repo.
- catherd installs three agents (`catherd-ro`, `catherd-worker`, `catherd-full`) with explicit
  permission rules into the opencode config dir (and the isolated one); `doctor` checks them.
  Enforcement: advisory.
- Totals from `opencode api GET /api/session/<id>` (tokens, cost, outcome); busy from
  `/api/session/active`; `interrupt` via `POST /api/session/<id>/interrupt`. Empty or failed API output
  counts as **not busy**.
- `provider.quota` and `provider.rate-limit` → `limit`; an in-progress retry on the latest message is
  surfaced early as a `retrying` delta.
- Discovery: `opencode-go/*` (Go, billing `subscription`) and `opencode/*` (Zen, billing `metered`),
  retrying once on the empty first list. Effort = the model's own variants, validated before dispatch.
- Default failover: Go `X` → Zen `X` when Zen lists `X`.
- Live test model: `opencode/space-bunny-free`.

### 6.4 Cursor (1.1)

`agent -p --output-format stream-json --trust --workspace <repo> --model <id> [--resume <chat>]`; each
effort is a separate model id from `agent --list-models`; tokens from `result.usage`, no cost; reply is
the last `assistant` message; kill after `result` + grace. Access: `read-only` → `--mode ask`,
otherwise `--force` with `--sandbox enabled`. Isolation requires a separate `HOME` plus
`CURSOR_API_KEY`, because Cursor loads Claude Code hooks and skills; the TUI says so.

### 6.5 Grok Build (1.2)

`grok --prompt-file <brief> --output-format streaming-json --cwd <repo> -m <model> --effort <e>
--always-approve --trust --no-auto-update -s <uuid>`; resume `-r <id>`. Access → Landlock profiles
(`read-only`, `workspace`, `off`) shipped in an isolated `GROK_HOME`; enforcement: enforced where
Landlock applies. Limits from the documented messages and code -32003; exit 2 → `cli-too-old`.

## 7. Profiles and Claude agents

### 7.1 Profile schema v1

```json
{
  "schema": 1, "name": "default", "objective": "cost",
  "jev": { "use": "auto" },
  "billing": { "codex": "chatgpt-plan", "claude": "claude-plan", "claude-code": "claude-plan",
               "opencode-go": "subscription", "opencode": "metered" },
  "roles": {
    "worker": { "enabled": true, "access": "workspace-write",
                "rungs": ["codex:gpt-6-luna#high", "codex:gpt-6-sol#medium",
                          "codex:gpt-6-sol#high", "codex:gpt-6-sol#xhigh"],
                "defaultRung": "codex:gpt-6-sol#medium" }
  },
  "harness": { "codex": { "isolated": false }, "claude-code": { "isolated": false },
               "opencode": { "isolated": false } },
  "failover": {}, "budget": {}, "timeouts": { "idleMin": 15, "wallMin": 90 },
  "preflight": { "confirm": false },
  "lock": { "heavy": "cpus/2" }, "notify": ["milestone", "finish", "blocked"]
}
```

- Every role key is optional; a missing role takes the built-in default. Adding a role never breaks a
  profile. Unknown fields are preserved.
- `access` defaults: architect, reviewer, researcher `read-only`; worker, writer, artist
  `workspace-write`; verifier, ui-reviewer `full`. `validate` warns (never errors) on a mismatch such as
  a verifier on `read-only`.
- `validate` errors: worker disabled; an enabled role with no usable rung; an unscored rung without a
  treat-like; a failover stand-in unscored or on the same backend; a rung whose backend is unknown.

### 7.2 Default profile (owner's setup: Codex/ChatGPT plan, Claude plan, OpenCode Go)

architect `claude:claude-opus-5-5#high`; verifier `claude:claude-opus-5-5#low`; worker as above;
reviewer `codex:gpt-6-sol#high`; ui-reviewer and artist `codex:gpt-6-sol#medium`; writer and researcher
`codex:gpt-6-luna#high`. Failover for each Codex rung: the best-matching Go model by treat-like, marked
`inferred`. Astra, Fable, Sonnet 5 and Haiku are in the catalog but not enabled.

### 7.3 ProfileService

The single writer of profiles, agent files and agent links, used by the TUI, the `catherd profile`
commands and MCP `profile_set`. Operations: `get`, `list`, `create`, `copy`, `delete`, `patch`,
`validate`, `diff`, `activate(name, repo?)`.

Agent files are named `catherd-<profile>-<role>-<model slug>-<effort>.md`. Links in
`~/.claude/agents` (or `CATHERD_CLAUDE_AGENTS_DIR`) cover the union of the active profile and every
repo-bound profile; relinking happens on every save and activation; only catherd's own symlinks are ever
replaced or pruned. Every operation that changes links returns the agents that need a new Claude Code
session.

## 9. TUI

Reference: opencode's TUI (also OpenTUI), studied in `docs/research/2026-09-25-opencode-tui.md`.
catherd mirrors its key engine, command model, dialogs, theme approach and component shapes, and keeps
its own staged-edit model and plain/NO_COLOR support.

### 9.1 Screens

One app, three tabs, plus `init`:

- **1 Status** (default): each backend (version, login, model count), Jev, Claude agents, plugin, each
  as `glyph word — detail` with the full fix command (copy with `y`); the active profile; the last five
  runs.
- **2 Profiles**: a profile switcher and one tree: roles → access row + backend → model → efforts;
  routing (objective, Jev), harness isolation, budget, failover, timeouts, notify. Each role shows its
  access mode and the backend's enforcement (`enforced`/`advisory`).
- **3 Runs**: the run list; Enter opens a run: live lanes (role, rung, elapsed, state), climbs, Jev
  decisions, budget bar, landed milestones; "updated Ns ago"; `p` pauses.
- **`init`**: linear steps in the normal screen; the summary and the plugin install commands print to
  stdout at the end.

Overlays: help (`?`), command palette (`:`/`ctrl+p`), save dialog with the diff, confirmations,
pickers (model, treat-like, failover), value editors.

### 9.2 Commands and keys

- **Engine:** `@opentui/keymap` (opencode's key engine) with its React binding. Contexts come from its
  mode stack (a dialog puts the keymap in modal mode), focus-scoped layers and priorities, mapped from
  the context stack global → tab → pane → dialog → input. The first match consumes the key.
- **One command model.** Every action is a keymap command `{ id, title, group, palette, run }`. The
  palette, footer hints, help overlay and any future mouse or event trigger all call `dispatch(id)`.
  There is no second registry; hints and help are generated, so they cannot drift.
- **Chords, as in opencode:** `ctrl+p` palette (with a "Suggested" group and live shortcuts);
  leader `ctrl+x` (2 s timeout): `<leader>1-3` tabs, `<leader>n` new profile, `<leader>l` profile list,
  `<leader>u`/`<leader>r` undo/redo, `<leader>q` quit.
- **Bare-letter keys** (`q`, `?`, `1`–`3`, `j`/`k`, `g`/`G`, `space`, `a`, `/`) stay for speed, but only
  in pane layers or guarded by "no text input focused". A focused input owns every printable key; a test
  types every bare-letter binding into every input and expects it to arrive as text.
- **Lists:** arrows plus `j`/`k`, paging, Home/End, `/` filter; delete is `ctrl+d` pressed twice (the
  row shows the armed state), as in opencode's session list. **Dialogs:** arrows or `ctrl+n`/`ctrl+p`
  move; the filter input owns letters; `enter` chooses; `esc` cancels.
- **Leaving:** `esc` backs out one level and never quits. `q` or `<leader>q` quits, confirming if a draft
  is dirty. `ctrl+c` quits when clean; when dirty, a second press within 1.5 s discards and exits 130.
  Cancelling a live run in Runs uses the "esc again" armed state.
- **Edits are staged** in a draft; `enter` never saves. `ctrl+s` opens the save dialog (diff, agent-file
  changes, what applies when) with Save / Save & make active / Cancel. Activation is its own command
  with a confirmation.
- **Configurable:** `config.json` `keybinds: { <command id>: string | string[] | "none" }`; unknown ids
  are rejected with `E_CONFIG_KEYBIND`. A test fails on a duplicate key in any reachable context or on a
  command without a title.

### 9.3 Look

- **Theme:** 16 semantic tokens (text, muted, accent, accentText, surface, surfaceRaised, backdrop,
  border, success, warning, error, info, selection, selectionText, diffAdd, diffDel). Accent ginger
  `#E8833A` on dark, `#B45309` on light (≥ 4.5:1 on white). Dark/light from the terminal
  (`waitForThemeMode`, falling back to dark).
- **Surfaces:** almost no borders; the selected row is filled with the accent and bold; dialogs are a
  raised panel over a dimmed backdrop at 60, 88 or 116 columns; toasts ("saved", "catalog refreshed")
  queue at the top right with a `┃` bar; empty states are one muted line.
- **State:** green/amber/red only for state, always with a word (`✓ ready`, `! not logged in`,
  `✗ missing`); `[x]` checkboxes; no emoji.
- **Motion:** braille spinner at 80 ms, shown only after 500 ms and kept at least 3 s; none under
  `--reduced-motion`.
- **Header:** one line with the version, profile, dirty count and the small mood face (`=^.^=`); the full
  mascot only on the `init` welcome and empty states.
- **Text:** end-of-line truncation only; ids, paths and commands wrap. 80×24 gives 19 content rows.
- `NO_COLOR` and `--plain` (ASCII glyphs, no colour) are honoured, beyond what opencode does.

### 9.4 Framework and code

- `@opentui/react`, `@opentui/core` and `@opentui/keymap`, all pinned exactly. No move to
  `@opentui/solid`: it needs a Babel transform, and catherd ships its TypeScript without a build step.
- Renderer: no mouse capture, `exitOnCtrlC: false`, alternate screen for the app only; anything the user
  must keep is printed to stdout after exit.
- Code: `commands.ts` (command and binding data), `state.ts` (pure reducer: drafts, history, dialogs),
  `effects.ts` (services injected), `providers/` (one per concern: theme, keymap, dialog stack, toasts,
  data), `views/`, `widgets/` (about 18 components, each mirroring an opencode counterpart). Runs data is
  polled off the render path, memoised by mtime.
- Code adapted from opencode (MIT) keeps its notice in `THIRD_PARTY_NOTICES.md` and a header line in each
  derived file.
- `CATHERD_STORY=1` opens an in-terminal storybook of every widget and view, for development.

## 10. Errors, logging, doctor, security

### 10.1 Errors

`CatherdError { code, message, fix?, cause? }`. Families: `E_CONFIG_*`, `E_BACKEND_*` (missing,
too-old, not-logged-in, model-unknown), `E_RUN_*` (not-found, corrupt, budget), `E_ADMIT_*` (rung,
duplicate, overlap), `E_JEV_*`, `E_IO_*`. MCP returns them as structured tool errors; the CLI prints
them and maps them to exit codes.

### 10.2 Logging

`<data>/logs/catherd-<date>.jsonl`, 7-day rotation, level via `--verbose` or `CATHERD_LOG`. Logged:
every MCP tool call with duration and outcome, every spawn (argv and env keys, never values),
reconciles, Jev calls. A redactor removes known secret values and `*_KEY`/`*_TOKEN` env values
everywhere. `catherd runs show <id> --debug` prints the record, `exit.json`, the stderr tail and the
event tail.

### 10.3 doctor

Checks: Bun version; each backend (installed, version ≥ min, logged in, discovery ok); Jev key
(present, test question); plugin installed and its version equal to the package's; agent links present
and not stale; the MCP server starts and answers `tools/list` over stdio; the heavy-lock directory is
writable, including from inside a Codex `workspace-write` sandbox; warnings for `full` access,
advisory enforcement and Cursor's weak isolation; credential file modes. Output: one row per check with
state, word and fix; `--json`; exit 3 when not ready.

### 10.4 Security

- Secrets never reach workers or logs; credential files are mode 600.
- Briefs by stdin/file, positionals after `--`, ids validated against patterns and the profile.
- Run files only through the path guard (symlink-aware); agent links only replace catherd's links.
- `preflight` runs with a timeout and a stripped env, lists its commands in the report, never as root,
  and can require confirmation.
- The plugin runs exactly its own package version; the marketplace is served from release tags.

## 11. Testing

1. **Unit:** routing and the approved-ladder pin, bars, catalog merge, cost rank, schemas, errors,
   the TUI keymap scopes and reducer.
2. **Adapter contract suite**, run against every adapter: fixture parsing (ok, limit, failed, too-old,
   resume, reconnect/retry), `plan()` argv/env per access mode and isolation, `finalize()` records. An
   adapter ships only when the suite passes.
3. **Simulators** replacing today's fake CLIs: `codex`, `claude`, `opencode` v2 (then `agent`, `grok`),
   each with `--version`, login state, model listing, stdin and `$PWD` handling, real error shapes and,
   for opencode, `/api/session/*`; driven by a scenario file (delay, exit code, file edits, events).
4. **Integration:** the real MCP server over stdio with an SDK client, end to end on simulators:
   run → route → preflight → dispatch → climb → failover → land → budget stop → cancel → server restart
   mid-run → reconcile.
5. **Concurrency and corruption regressions:** parallel overlapping dispatch, concurrent reconcilers
   (no duplicate records), truncated JSONL, corrupt `meta.json`, reused pid.
6. **TUI:** keymap scope tests (including bare letters typed into focused inputs), reducer units, a fake
   clock for motion; snapshot frames at 80×24, 100×30, 120×40 in unicode and plain, with
   invariants (footer visible, width respected, plain is ASCII); keypress scenarios with deterministic
   flushes; a tmux PTY smoke test. `docs/tui-frames.md` is generated from the snapshots.
7. **Live** (`CATHERD_LIVE=1`, owner's machine): one cheap task per backend (Codex Luna low,
   claude-code Haiku, opencode `space-bunny-free` or Go) and one tiny orchestrated run on a sample repo.
8. **Fixture capture:** `catherd capture-fixtures` records real streams, strips secrets and home paths,
   and writes `test/fixtures/adapters/<backend>/<cli-version>/` by default (`--out`).

Hygiene: no wall-clock sleeps (fake clock or deterministic flush), an isolated `CATHERD_HOME` per test,
no global env mutation, a coverage floor in CI.

## 14. Risks

- **Vendor CLIs change monthly.** Adapters pin a minimum version, `probe` reports drift, fixtures are
  stored per CLI version, and the contract suite makes a new version's breakage visible.
- **opencode v2's permission behaviour is partly undocumented.** Enforcement is labelled advisory, and
  the live test covers a read-only role attempting a write.
- **Benchmarks go stale.** Scores are data with sources and dates; own-run timings replace hand-typed
  speeds.
- **Native Claude spend is self-reported** through `record_agent_run`; the report marks those numbers
  as reported, not measured.
- **OpenTUI is 0.x.** It is pinned exactly and wrapped behind `widgets/`.
