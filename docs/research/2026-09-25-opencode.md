# opencode in catherd: OpenCode Zen and Go, the headless interface, why today's integration fails, and a redesign

Research date: 2026-09-25. Everything marked **[verified]** was run live in this sandbox against
`opencode-ai@1.18.32` (npm `latest`, the v1 line) and `@opencode/cli@2.0.16` (the v2 line), with an
isolated HOME and the free Zen models, or was read in the opencode source at `anomalyco/opencode`
(branch `dev` = 1.18.32, branch `v2` = 2.0.16, cloned 2026-09-25). **UNVERIFIED** marks what I could
not check, usually because it needs a paid Zen key or a Go subscription.

Raw captures that can serve as fixtures are in `research/opencode-samples/` next to this file.

---

## 0. The headline finding: there are two opencode CLIs, and they are incompatible

| | opencode **v1** | opencode **v2** |
|---|---|---|
| npm package | `opencode-ai` (`latest` = **1.18.32**, 2026-09-21) | `@opencode/cli` (`latest` = **2.0.16**, 2026-09-24) |
| Other installs | `curl … opencode.ai/install` | `curl -fsSL https://opencode.ai/v2/install \| bash`, `brew install anomalyco/tap/opencode-v2`, `npm i -g @opencode/cli` |
| `--version` output | `1.18.32` | `opencode v2.0.16` |
| Architecture | in-process server per `run` | a **shared background service** per user (`opencode service …`), plus `--standalone` for a private server |
| Model syntax | `-m provider/model` plus a separate `--variant high` | `-m provider/model#variant` (no `--variant` flag) |
| `opencode api …` | does not exist | exists (calls the running server) |
| `run --standalone` | unknown flag, prints help, **exit 1** | exists |
| HTTP API | `/session/:id/...`, `/session/:id/abort`, SDK `@opencode-ai/sdk` 1.18.32 | `/api/session/{id}/...`, `/api/session/{id}/interrupt`, client `@opencode/client` 2.0.16 |
| Permission config | `permission: { bash: "ask", ... }` | `permissions: [{action, resource, effect}]`, where `bash`→`shell` and `task`→`subagent` |

Sources: https://www.npmjs.com/package/opencode-ai, https://www.npmjs.com/package/@opencode/cli,
https://opencode.ai/update/api/latest/cli/npm (returns `{"version":"2.0.16","metadata":{"package":"@opencode/cli",…"ref":"refs/heads/v2"}}`),
https://opencode.ai/v2/docs/ (install section), https://opencode.ai/v2/docs/migrate-v1/ ("OpenCode 1 and
OpenCode 2 both use the opencode command and are no longer installed side by side by default"),
https://github.com/anomalyco/opencode/releases/tag/v2.0.16.

catherd was written and "verified live" against **v2.0.15** (docs/dependencies.md:49, plans
2026-09-24-01-core.md:1755, 2026-09-24-04-tui.md:827), and most of its flags are correct **for v2**. But
its own install hint `npm i -g opencode-ai` (src/tui/backends.ts:23) installs **v1.18.32**, which rejects
or ignores almost every flag catherd passes. Its version probe does not check the major version. A user
who follows catherd's fix command gets a CLI that fails every dispatch. This alone can explain
"practically doesn't work", and several v2-only bugs come on top of it (section 3).

## 1. OpenCode Zen and OpenCode Go

### 1.1 OpenCode Zen: pay as you go, a curated gateway

- What it is: "a list of tested and verified models provided by the OpenCode team", run as an **AI
  gateway**. The team benchmarked model and provider pairs and serves only the ones it recommends. It is
  optional, and it works like any other provider. https://opencode.ai/docs/zen
- Pricing: **pay as you go**, per 1M tokens (input, output, cached read, cached write), "at cost". Card fees
  (4.4% + $0.30) are passed through. You add credits. **Auto-reload** adds $20 when the balance falls below
  $5; you can change the amount or turn it off. Monthly spend limits can be set per workspace and per
  member. Workspaces (teams) are free during the beta. **Bring your own key** is supported for OpenAI and
  Anthropic. https://opencode.ai/docs/zen
- Provider id **`opencode`**, model ids **`opencode/<model-id>`**, e.g. `opencode/gpt-6-sol`. In v2 the
  provider is shown as "OpenCode Console". [verified: v2 `GET /api/integration`]
- Endpoints: `https://opencode.ai/zen/v1/{responses|messages|chat/completions|models/<id>}`, depending on
  the model family. There is a public model list at **https://opencode.ai/zen/v1/models** (it needs no key;
  [verified] it returned 82 ids today).
- Models today (docs table plus `/zen/v1/models`, 2026-09-25): GPT 6 Astra/Sol/Luna; GPT 5.6
  Sol/Terra/Luna; GPT 5.5 (+Pro); 5.4 (+Pro/Mini/Nano); 5.3 Codex (+Spark); 5.2 (+Codex); 5.1 (+Codex,
  Codex Max/Mini); 5, 5 Codex, 5 Nano; Claude Fable 5.1/5, Opus 5.5/5/4.8/4.7/4.6/4.5, Sonnet
  5/4.6/4.5/4, Haiku 4.5; Gemini 3.8/3.7/3.6/3.5 Flash, 3.5 Flash Lite, 3.1 Pro, 3 Flash; Grok
  4.7/4.6/4.5, Grok Build 0.1; Muse Spark 1.3/1.2; Qwen3.8 Max/Flash, 3.7 Max/Plus, 3.6/3.5 Plus;
  DeepSeek V4.1 Flash, V4 Pro/Flash/Flash Vision Exp; MiniMax M3/M2.7/M2.5; GLM 5.3 Flash/5.3/5.2/5.1/5;
  Kimi K3/K2.7 Code/K2.6/K2.5; Jev 1.13 (a "System One" decision model, not a chat or coding model).
  **Free** models: big-pickle, space-bunny-free, mimo-v2.6-flash-free, mimo-v2.5-free,
  ling-3.0-flash-fin-free, nemotron-3-ultra-free, nemotron-3.5-lightning-free,
  muse-spark-1.3-contributor-free, jev-1.13-free. Most free models **may use your data for training**
  (see the Privacy section of the page), so catherd should flag them.
- Example prices: Claude Opus 5.5 is $4 in / $20 out; GPT 6 Sol is $2 / $10 (≤272K); GPT 6 Luna is $0.10 /
  $0.50; Kimi K3 is $3 / $15; GLM 5.3 is $1.40 / $4.40; DeepSeek V4 Flash is $0.14 / $0.28.
  https://opencode.ai/docs/zen
- Zen ids that catherd already has for Codex or Claude map one to one: `opencode/gpt-6-sol`,
  `opencode/gpt-6-luna`, `opencode/claude-opus-5-5`.

### 1.2 OpenCode Go: a $10/month subscription for open models

- What it is: "a low cost **$10/month subscription** that gives you reliable access to popular open coding
  models". It is aimed at international users. Only one member per workspace can subscribe.
  https://opencode.ai/docs/go, https://opencode.ai/v2/docs/console/go/
- Usage model: each model has a **monthly dollar limit** ($15, $30 or $60 of list-price usage, depending on
  the model). On top of that, a **5-hour** window allows 20% of it and a **weekly** window 50%. With "Use
  balance" turned on in the console, Go falls back to your Zen balance once you pass a limit, instead of
  blocking. Free models keep working after the limit. DeepSeek models have peak and off-peak prices.
- Provider id **`opencode-go`**, model ids **`opencode-go/<model-id>`**, e.g. `opencode-go/kimi-k3`.
  Endpoints are `https://opencode.ai/zen/go/v1/...`. Public list: **https://opencode.ai/zen/go/v1/models**
  [verified].
- Models today: Grok 4.7/4.6, GLM-5.3-Flash/5.3/5.2/5.1, GPT 6 Luna, GPT 5.6 Luna, Kimi K3/K2.7 Code/K2.6,
  LongCat-2.0, MiMo-V2.6-Flash/-Pro, MiMo-V2.5/-Pro, MiniMax M3/M2.7, Muse Spark 1.3/1.2 Contributor
  (limited regions), Qwen3.8 Max/Flash, Qwen3.7 Max/Plus, Qwen3.6 Plus, DeepSeek V4.1 Flash, V4 Pro, V4
  Flash, V4 Flash Vision Exp, Hy4 preview, Hy3, Space Bunny Free. [verified: `opencode models
  opencode-go` lists 32 ids when a key is present]
- Go asks clients to send a stable `x-opencode-session` header and their own user-agent. opencode itself
  does this, and catherd does not need to.

### 1.3 Auth

- Get the key from the console (https://opencode.ai/auth, then Zen, then an API key; or subscribe to Go
  there). In the TUI, run `/connect`, pick "OpenCode Zen" or "OpenCode Go", and paste the key.
- CLI v1: `opencode auth login` (an alias of `opencode providers login`) stores the key in
  `~/.local/share/opencode/auth.json`. `opencode auth list` lists it. https://opencode.ai/docs/cli
- CLI v2: `opencode auth login opencode --method key` or `opencode auth login opencode-go --method key`.
  Key entry needs a TTY. The `opencode` provider also has an OAuth "device" method, "OpenCode Console
  account". `opencode auth list --format json` returns `[{id, name, connections:[{type, name}]}]`
  [verified]. https://opencode.ai/v2/docs/cli/providers/
- Environment: both `opencode` and `opencode-go` accept **`OPENCODE_API_KEY`** [verified in the v2
  integration list and in the v1 listing with a fake key]. **In v2 the env must reach the background
  service**, not the client: `opencode service set env OPENCODE_API_KEY …`, or `--standalone` with the
  variable set. https://opencode.ai/v2/docs/cli/providers/
- UNVERIFIED: whether a single console key authorizes both Zen and Go. The docs describe the same console
  "API key" for both, and the Go subscription is attached to the workspace.

### 1.4 Listing the user's models from the CLI

- `opencode models [provider]` lists `provider/model` lines for **connected providers only**.
  - v1: `--verbose` prints a JSON object per model with `variants`, `cost`, `limit` and `capabilities`, and
    `--refresh` refreshes from models.dev. [verified]
  - v2: plain list only; no provider argument and no `--verbose` [verified with `--help`].
  - The full metadata is in `opencode api model.list` (`GET /api/model`). Each entry has
    `{id, providerID, name, variants:[{id, settings}], cost:[…], limit:{context, output}, capabilities:{tools, input[], output[]}, status, enabled}`.
    [verified] Sample: `opencode-samples/v2-api-model-list-nokey.json`.
- With **no key at all**, v1 and v2 still list the 7 free `opencode/*` models, and they run
  (`apiKey:"public"`). [verified: `opencode/space-bunny-free` and `opencode/big-pickle` answered]
- With **any** key (a fake one works), the whole Zen catalog (76) and Go catalog (32) are listed [verified].
  So the listing means "the catalog for providers that have a credential". It does not show the actual
  entitlement: a key with no credit, a Go limit, or a model an admin disabled for the workspace only shows
  up at request time, as `provider.auth`, `provider.no-route` or `provider.quota` errors.
- The catalog source is still models.dev, cached in `~/.cache/opencode/models.json`
  (`OPENCODE_MODELS_URL` overrides it), and opencode adds its **own variants**. Those variants differ from
  models.dev `reasoning_options` for some models (see §3.2).
- **Warm-up race (v2)**: the first `opencode models` or `api model.list` after the service (re)starts
  returned **0 models** twice, and returned 302 on the next call [verified]. Discovery must retry when the
  list is empty.

## 2. The headless interface

### 2.1 `opencode run` flags

**v2.0.16** (`opencode run --help`, [verified]):
`--standalone`, `--server <url>`, `-c/--continue`, `-s/--session <id>`, `--fork`, `-m/--model
provider/model#variant`, `--agent <id>`, `--format default|json`, `-f/--file <path>`, `--title`,
`--thinking`, `--auto`. Global flags: `--log-level`, `--print-logs` (server logs need `--standalone`).
Hidden flags: `--yolo`, `--dangerously-skip-permissions` (the same as `--auto`). There is no `--variant`,
no `--dir`, and no `--port`.
- The working directory comes from **`$PWD`**, not from the process cwd (`root = options.root ??
  process.env.PWD ?? process.cwd()`, `packages/cli/src/run/run.ts:73` on the v2 branch). [verified:
  spawned with `cwd=repo` and `PWD=other`, `pwd` inside the session printed `other`]
- The message comes from positional args and/or **piped stdin**; the two are joined. [verified: a brief read
  from stdin with no positional arg works]
- A positional message that **starts with `-`** is parsed as flags: the CLI prints help and exits 1.
  `--` fixes this. [verified]

**v1.18.32** (`opencode run --help`, [verified]):
`--command`, `-c`, `-s`, `--fork`, `--share`, `-m provider/model`, `--agent`, `--format default|json`,
`-f`, `--title`, `--attach <url>`, `-p/-u` (basic auth), `--dir`, `--port`, **`--variant <name>`**,
`--thinking`, `-i/--interactive`, `--auto`. https://opencode.ai/docs/cli

**Effort and variant.** Variants are per model, named options (usually reasoning effort) that come from
the catalog. v2 adds `#variant` to the model reference, and an unknown variant is an error:
`{"type":"error","error":{"type":"provider.no-route","message":"Variant unavailable for opencode/big-pickle: ultra"}}`,
exit 1 [verified]. Without `#`, the model's default applies (sessions report `variant:"default"`).
https://opencode.ai/v2/docs/models/ ("Variant names come from the selected model's current catalog
metadata … an unknown variant produces a model-resolution error"). v1 uses `--variant`, and
`-m model#high` fails with `ProviderModelNotFoundError: Model not found: opencode/big-pickle#high`
[verified]. https://opencode.ai/docs/models (Variants)

Current variant names for Zen and Go (from `opencode models <p> --verbose` on 1.18.32, which match the v2
`model.list` for the models I checked):
- GPT 6 / 5.6 family: `none low medium high xhigh max`. GPT 6 Astra: `low…max`.
- Claude Opus 5.5 / 5 / 4.8 / 4.7, Sonnet 5, Fable: `low medium high xhigh max`. Haiku 4.5 and Sonnet
  4 / 4.5: `high max`.
- Gemini 3.x Flash: `minimal low medium high` or `low medium high`.
- DeepSeek V4 Flash / 4.1 Flash: `low high max`. V4 Pro: `high max`. GLM 5.3: `low high max`. GLM 5.2:
  `high max`. Kimi K3: `max` only.
- **No variants**: Kimi K2.x, MiniMax M2.x, GLM 5 / 5.1, MiMo, big-pickle.
- Go-only oddities: `opencode-go/minimax-m3` = `none thinking`; `hy3` = `none low high`; `hy4-preview` =
  `none high`; `qwen3.8-max` = `low medium xhigh` (Zen `qwen3.8-max` has none).
- Full dumps: `opencode-samples/v1-models-opencode*-verbose.txt`.

### 2.2 The JSON event stream (`--format json`)

One JSON object per line. Every event has `{type, timestamp, sessionID, …}`.

| type | payload | notes |
|---|---|---|
| `step_start` | `part:{id, messageID, sessionID, type:"step-start", snapshot}` | |
| `text` | `part:{…, type:"text", text, time:{start,end}}` | one per finished text part |
| `reasoning` | `part:{…, type:"reasoning", text}` | only with `--thinking` |
| `tool_use` | `part:{type:"tool", tool, state:{status:"completed"\|"error", input, output\|error, time}}` | only finished tools |
| `step_finish` | `part:{type:"step-finish", reason, snapshot, cost, tokens:{input, output, reasoning, cache:{read, write}}}` | **token usage lives here** |
| `error` | v2: `error:{type, message}`, e.g. `provider.no-route`, `aborted`, `unknown`. v1: `error:{name, data:{message, ref}}` | |

Sources: v1 `packages/opencode/src/cli/cmd/run.ts:678-800` (dev branch); v2
`packages/cli/src/run/noninteractive.ts:94-505` (v2 branch). Samples: `opencode-samples/*.jsonl`.

Caveats [verified]:
- **v2 often drops the final `step_finish`.** Once the prompt call returns, the client is "finalizing" and
  skips non-`session.execution.*` events (`noninteractive.ts:222`). A one-step run had no `step_finish` at
  all, and a three-step run had two. Summing stream tokens therefore **undercounts**; use the session totals
  (§2.4).
- v1 emits `step_finish` with tokens and cost for every step, so catherd's note "opencode's stream has no
  token usage" (src/core/harness.ts:38, plan 01-core.md:1753) is wrong for both versions.
- Stream errors in v2 use `error.type` values `provider.auth`, `provider.no-route`, `provider.quota`,
  `provider.rate-limit`, `provider.timeout`, `provider.content-filter`, `provider.invalid-request`,
  `provider.internal`, `provider.transport`, `provider.unknown`, `aborted` and `unknown`
  (`packages/core/src/session/to-session-error.ts`).
- Rate limits: v2 retries `RateLimit`, `ProviderInternal` and unknown provider errors **up to 10 times**,
  backing off 2 to 10 s, but a provider `retry-after` of up to **15 min per gap** is honoured. The CLI
  stream prints **nothing** while it retries. `QuotaExceeded`, auth errors and no-route errors fail at once
  (`packages/core/src/session/runner/retry.ts`). A retrying assistant message carries
  `retry:{attempt, at, error}` (`packages/schema/src/session-message.ts: AssistantRetry`), and the durable
  event `session.retry.scheduled` is emitted. UNVERIFIED which of `provider.quota` or
  `provider.rate-limit` a Go 5-hour or weekly limit produces.

### 2.3 Exit codes

- v2: **0** means the execution succeeded. **1** means any error: model or variant unavailable, provider
  failure, a permission that was auto-rejected (the run aborts, §2.6), or a server-side interrupt from
  another client. **130** means SIGINT: the client interrupts the session server-side, then exits.
  A second SIGINT exits immediately. [verified: 0, 1 (bad model, bad variant, rejected permission,
  `api … /interrupt`); 130 is from source, `noninteractive.ts:633-640`]
- v1: 0 or 1 (`process.exitCode = 1` on `session.error` or a prompt error).
- Both: a zero exit code does **not** mean the model did anything useful. Parse the reply.

### 2.4 Session totals, busy state, interrupt (v2, via `opencode api`)

`opencode api <METHOD> <path>` or `opencode api <operationId>` calls the running server with the right
auth. Useful calls [all verified on 2.0.16]:
- `GET /api/session/<id>` → `{"data":{"id","model":{"id","providerID","variant"},"cost","tokens":{"input","output","reasoning","cache":{"read","write"}},"outcome":"succeeded|interrupted|…","time":{…,"idle"}}}`.
  This gives **totals for the whole session, tokens included**, and it also works for sessions created by
  a `--standalone` run, because the DB is shared.
- `GET /api/session/active` → `{"data":{"ses_…":{"type":"running"}}}`, or `{}` when nothing runs. This is
  the busy signal: simpler and cheaper than paging through messages.
- `GET /api/session/<id>/message` → newest first, cursor-paginated. After the run it starts
  `{type:"idle", outcome}`. While running, the first entry is the in-flight `assistant` message (with
  `retry` while retrying).
- `POST /api/session/<id>/interrupt` → `{"interrupted":true}`. The client then gets
  `error {type:"aborted","message":"Step interrupted"}` and exits 1. A running `shell` tool is killed
  (`sleep 40 && touch done.txt` never wrote the file). The session `outcome` becomes `"interrupted"`.
- `GET /api/model` (`model.list`), `GET /api/integration`, `GET /api/agent`, `POST
  /api/experimental/session/<id>/wait`.
- The full API reference is at https://opencode.ai/v2/docs/api/, or run `opencode api GET /openapi.json`
  (136 operations).
- **Killing the v2 client (SIGTERM) does not stop the session.** It keeps running on the background
  service and keeps editing files [verified: `done.txt` appeared 35 s after the client was killed]. So the
  server-side interrupt that catherd already does is required. SIGINT to the client does the same
  interrupt.
- `opencode api` with no location parameter resolves the location to the **home directory**. That does not
  matter for id-based session calls, but it does for `model.list` and `agent.list`
  (`--param location[directory]=<repo>`). [verified]

v1 has no `api` command. Its server (`opencode serve`, `/session/:id`, `POST /session/:id/abort`, `GET
/session/status`, SSE `/event`) is reachable only when catherd starts or attaches to a server
(https://opencode.ai/docs/server). The v1 SDK is `@opencode-ai/sdk` (https://opencode.ai/docs/sdk).

### 2.5 `opencode serve` and SDK as an alternative to parsing the CLI

- v2: every CLI already talks to the background service over HTTP. `@opencode/client` 2.0.16 exposes
  `OpenCode.make({baseUrl, headers})` plus `service.discover()` and `service.ensure()`, which find or start
  the service from its registration file. Its npm description reads "**Private generation target** for
  clients derived directly from OpenCode's authoritative Effect HttpApi", and the docs call the HTTP API
  "Experimental". https://opencode.ai/v2/docs/migrate-v1/ ("Use the @opencode/client package to access the
  released V2 API"), https://opencode.ai/v2/docs/api/
- v1: `@opencode-ai/sdk` (`createOpencode()` starts a server; `client.session.prompt`, `session.abort`,
  `event.subscribe`). It does **not** speak the v2 API.

### 2.6 Permissions in non-interactive runs (so a run never blocks)

- Neither version ever blocks on a prompt in `run`. Every `permission.asked` is answered at once: `once`
  with `--auto`, otherwise **`reject`** (v1 `run.ts:801-820`; v2 `noninteractive.ts:131-153`). v1 also
  denies `question`, `plan_enter` and `plan_exit` for run sessions.
- **v2 difference:** a rejected permission also **interrupts the whole session**. The run ends with
  `error {type:"aborted","message":"Step interrupted"}` and exit 1 [verified: a read of a file outside
  the repo, without `--auto`]. In v1 the model only gets a tool error and carries on.
- Default policy in v2, for every agent (https://opencode.ai/v2/docs/permissions/, and verified with
  `opencode debug agents`): `*:* allow`, then `external_directory:* ask`, `read:*.env ask`,
  `read:*.env.* ask`, `read:*.env.example allow`, and allow for opencode's own tmp, tool-output and config
  dirs. Any rule that resolves to "ask" becomes a reject, which aborts the run, unless `--auto` is set.
  `--auto` never overrides an explicit `deny`.
- Built-in agents in v2: `build` (primary, everything allowed); `plan` (primary, edits denied except plan
  files, **shell allowed**); `explore` (**subagent**: `*:* deny`, then allow read, glob, grep, webfetch
  and websearch; no shell; no subagents); `general` (subagent). `run --agent explore` worked as the main
  agent on 2.0.16 [verified: it had only read tools and refused to edit], but the docs say a subagent
  "runs only in a child session through the subagent tool", so relying on it is fragile.
  https://opencode.ai/v2/docs/agents/
- v1: `run --agent explore` prints `agent "explore" is a subagent, not a primary agent. Falling back to
  default agent` and runs **build** [verified]. Together with `--auto`, a "read-only" role then gets full
  write and shell access with every ask auto-approved.
- Read-only setup: define a custom **primary** agent whose permissions end in explicit denies, e.g.
  `[{action:"*",resource:"*",effect:"deny"}, {read/glob/grep allow}, {shell allowlist for "git diff *",
  "git log *", "rg *"…}]`, and run it with `--auto` so the remaining asks (external dirs, `.env`) do not
  abort the run. In v2, agents are markdown files in `~/.config/opencode/agents/<id>.md` or
  `<repo>/.opencode/agents/`, or `agents.<id>` in any `opencode.json(c)`. The background service reads
  **global and project** config. The client env (`XDG_CONFIG_HOME`, `OPENCODE_CONFIG_CONTENT`) does not
  reach it unless you run `--standalone`. https://opencode.ai/v2/docs/agents/,
  https://opencode.ai/v2/docs/cli/
- There is no OS sandbox. Shell runs "with the host user's filesystem, process, and network authority";
  directory inference from command text is "best effort". Read-only therefore means "no edit tool and no
  shell, or an allowlisted shell". It is weaker than Codex's `read-only` sandbox.

## 3. Why catherd's opencode integration fails (file:line)

Severity: **[B]** breaks every run, **[H]** breaks a common case or causes wrong results, **[M]** degraded
behaviour or missing data, **[L]** cosmetic or rare.

### 3.1 Install, version and login

1. **[B] The install hint installs the wrong major version.** `src/tui/backends.ts:23`
   `install: "npm i -g opencode-ai"` installs **v1.18.32** (npm `latest`). Everything in
   `src/core/opencode.ts` targets v2.0.15: `-m model#effort` (fails in v1 with ProviderModelNotFound),
   `--standalone` (unknown flag, exit 1), and `opencode api` (not a command in v1). Nothing detects v1:
   `probe()` in `src/tui/backends.ts:45-53` keeps the version string but never checks it, and
   `RunStatus` already has `"cli-too-old"` (`src/types.ts:136`), which only the Codex path uses. Fix:
   require `opencode --version` to match `^opencode v2\.`, and change the fix hint to `npm i -g
   @opencode/cli` or `curl -fsSL https://opencode.ai/v2/install | bash` (remove v1 first).
2. **[H] The "logged in" check is always true.** `src/tui/backends.ts:26` treats `auth list` exit 0 plus
   non-empty stdout as logged in. With **zero** credentials, v1 prints a "0 credentials" header and v2
   prints env connections such as `GitHub Copilot GITHUB_TOKEN environment`, both with exit 0 [verified].
   It also never checks that `opencode` (Zen) or `opencode-go` is connected, which is the thing that
   matters here. Use `opencode auth list --format json` and look for `id ∈ {opencode, opencode-go}` with
   `connections.length > 0`. Even with no connection, free `opencode/*` models work.

### 3.2 Model catalog (the "built as if it were OpenRouter" part)

3. **[H] Every model on models.dev is treated as an opencode model.**
   `src/routing/catalog.ts:82-93` loads `catalog/models-dev.json` (1.4 MB, **7,056** models from roughly
   100 providers: llmgateway, nano-gpt, kilo, openrouter, vercel, …) and pushes each one as `backend:
   "opencode"`. Only the providers the user has credentials for can run; for a Zen/Go user that is two
   providers (108 models). The role matrix (`src/tui/matrix-model.ts:118-135`) groups "capable models"
   per backend, so the opencode group holds thousands of rows, almost none of which work. The spec said
   the list would come from `opencode models` (docs/specs/2026-09-24-catherd-design.md:205), but the code
   never calls it.
4. **[H] Efforts come from models.dev, not from opencode's variants.** `src/routing/catalog.ts:202-204`
   takes `reasoning_options.values`, and `:91` always prepends `"default"`. opencode's variant ids are its
   own and sometimes differ: `opencode-go/minimax-m3` = `none, thinking`; `hy3` = `none, low, high`;
   `opencode-go/qwen3.8-max` = `low, medium, xhigh` while Zen's has none. Many models have **no** variants
   at all. A rung built from a models.dev effort that opencode lacks fails at once with `Variant
   unavailable for …` [verified error shape]. The snapshot is also a copy with a date: it goes stale as
   Zen and Go change weekly.
5. **[M] The provider-prefix fallback.** `src/mcp/runs.ts:114-118` `backendOf()` treats any id containing
   `/` as opencode. That is harmless, but it means a typo or an unknown provider only fails at dispatch
   time, with an opencode `provider.no-route` error rather than a catalog error.
6. **[M] opencode rungs are never scored.** `catalog/catalog.json` scores only `gpt-6-luna`,
   `gpt-6-sol` and `claude-opus-5-5`, and `treatLike` is `{}`. No opencode rung is scored by default, even
   `opencode/gpt-6-sol#high` or `opencode/claude-opus-5-5#high`, which are the same models catherd
   already scores.

### 3.3 Launching the run (`src/core/opencode.ts`)

7. **[H] opencode runs in catherd's directory, not the repo's.** `src/core/opencode.ts:176` passes
   `env: process.env` (or a copy of it), so `PWD` is the catherd MCP server's own `$PWD`. opencode v2
   resolves its working directory from **`$PWD`** and ignores the spawn `cwd` [verified]. Whenever the
   server's PWD is not `run.meta.repo` (a Claude Code session opened in a subdirectory, the plugin
   started from elsewhere, a run on another repo), the worker reads and edits the **wrong tree**, and
   `changedOwned` reports nothing. Fix: `env: { ...env, PWD: o.cwd }`. (Codex has no such problem;
   UNVERIFIED how often Claude Code's MCP launch leaves PWD different from the repo in practice.)
8. **[H] A brief is passed as a positional argv argument.** `src/core/opencode.ts:45`. A brief that starts
   with `-` (YAML front matter `---`, a `- bullet` first line) makes the CLI print help and exit 1
   [verified]. Linux caps a single argv string at 128 KiB (MAX_ARG_STRLEN), so a large fix brief with
   pasted logs fails with E2BIG (UNVERIFIED for catherd's brief sizes). Fix: send the brief on stdin
   (`runChild` already supports `stdinFile`) [verified: v2 reads a piped message], or at least put `--`
   before it.
9. **[H] Read-only roles.** `src/core/opencode.ts:27-33` adds `--agent explore --auto` for read-only roles.
   - v1: falls back to **build** with `--auto`: full write and shell access, every ask approved
     [verified fallback message].
   - v2: works today [verified] but relies on undocumented behaviour (explore is a subagent). Explore also
     has **no shell**, so a reviewer or researcher cannot run `git diff`, tests or `rg`. `--auto` also
     approves `.env` reads and external directories.
10. **[H] Worker roles abort on the first "ask".** `src/core/opencode.ts:28-33`: `workspace-write` (worker,
    artist, writer) passes no `--auto`, so an ask (reading or editing outside the repo, reading `.env`,
    shell touching external dirs) is auto-rejected. **In v2 that aborts the whole run** with `aborted: Step
    interrupted` and exit 1 [verified]. catherd records it as `failed` with the unhelpful message "Step
    interrupted".
11. **[M] Isolated mode.** `--standalone` (`src/core/opencode.ts:35`) with an empty `XDG_CONFIG_HOME`
    works on v2 [verified: the session ran, and its cost and tokens were readable through the background
    service]. On v1 it exits 1 at once. An isolated run also loses any agent that catherd would define in
    the user's global config, so catherd must write its agents into its own isolated config dir too (§4.4).

### 3.4 Watching, finishing and accounting

12. **[H] The busy check never says "stuck".** `src/core/opencode.ts:59-66`:
    `JSON.parse(api(...) || "{}")`, then `res?.data?.[0]?.type !== "idle"`.
    - When `opencode api` prints nothing (v1, which has no `api` command, exit 1 and empty stdout; the
      service is not reachable; a timeout), the parse gives `{}`, and `undefined !== "idle"` means
      **busy**. The idle watchdog then postpones itself forever (`:163-165`), and a hung v1 or v2 run never
      times out.
    - On v2, while the provider is **rate-limited and retrying** (up to 10 attempts, up to 15 min per gap)
      the newest message is the assistant one, so it also counts as busy. There are no events and no
      timeout during that time.
    - If stdout is not valid JSON, the `catch` returns `false`, "not busy", and a legitimately busy run can
      be killed.
    - Prefer `GET /api/session/active` and check `data[id]`. Treat "unknown" as its own state with a hard
      cap, and read `retry` on the newest message to detect limits (§4.5).
13. **[M] Tokens are always zero.** `src/core/opencode.ts:123` hardcodes `tokens: { input: 0, cached: 0,
    output: 0 }`, even though the same `GET /api/session/<id>` call it already makes for cost
    (`:100`) returns `data.tokens` [verified]. As a result `recordHarness` (`src/core/harness.ts:36-40`)
    skips opencode, and any `budget.tokens` or harness estimate ignores opencode runs.
14. **[H] Limits are never reported as `limit`, so failover never happens.** `src/core/opencode.ts:105-111`
    maps every error to `"failed"`. `src/mcp/dispatch.ts:131` triggers failover only on
    `status === "limit"`, so a Go 5-hour or weekly limit or an empty Zen balance never fails over and is
    not flagged as a quota problem. Map `error.type ∈ {provider.quota, provider.rate-limit}` (and
    `provider.auth` for an empty balance, UNVERIFIED) to `limit`.
15. **[M] The v1 error message is lost.** `src/core/opencode.ts:81` reads `e.error?.message`. v1 errors are
    `{name, data:{message}}` [verified], so the record says just `"error"`. (v2 matches.)
16. **[M] The reply is the concatenation of every text part.** `src/core/opencode.ts:80,95`. Intermediate
    narration ("I'll run that command.") is joined into the reply. `parseReplyStatus` looks for the
    `STATUS:` line, so this mostly works, but the reply file is noisy. Keeping only the last assistant
    message's text (from the API) would be cleaner.
17. **[L] The stream tokens are dropped.** v1 `step_finish` carries tokens, and v2 does sometimes. It is not
    needed if §13 is fixed through the API.
18. **[L] The cost API is v2-only, and `api` is spawned without `--standalone` or a location.** This is fine
    for id-based calls [verified]. `api()` uses `Bun.spawnSync` with no timeout (`:52`), so a wedged
    service blocks the MCP server's event loop. Add `timeout`.
19. **[L] `opencodeConfigHome()`** (`:18-22`) makes `<data>/opencode-home/config`. With XDG semantics
    opencode reads `<that>/opencode/opencode.json` and `<that>/opencode/agents/`, so catherd's isolated
    agents would go there.

### 3.5 Tests and docs that hide the problems

20. `test/fixtures/bin/opencode` accepts any argv. It has no `--version`, no `auth list`, no `models` and no
    stdin, ignores `$PWD`, and its `api GET <session>` returns cost only. So none of issues 1-2 or 7-14 can
    show up in tests. `test/fixtures/opencode/*.jsonl` were written by hand: no `timestamp`, no part ids,
    no `step_finish`, and `error.jsonl` uses a free-form `message` rather than a real v2 `error.type`.
    `test/opencode.test.ts:29` uses `openrouter/qwen/qwen3-coder#high` as the canonical rung, which is
    the OpenRouter mental model.
21. There is no live opencode test (`test/live/` has codex, jev and spike). docs/ideas.md:36: "an opencode
    lane … only run in tests, never in a real run".
22. docs/dependencies.md:49-63 records the v2.0.15 facts, but not that npm's `opencode-ai` is v1. Its
    install instructions and the TUI hint contradict it.

## 4. Recommended design

### 4.1 Target opencode v2 only, and say so

- Support `opencode v2.x` and refuse v1 with `status: "cli-too-old"` and a fix line:
  `npm i -g @opencode/cli` (or `curl -fsSL https://opencode.ai/v2/install | bash`, or `brew install
  anomalyco/tap/opencode-v2`), "remove opencode-ai v1 first". Parse `opencode --version` =
  `opencode v2.0.16`.
- Why v2: the owner's intent (Zen and Go) is served equally by both, but v2 has what a headless harness
  needs: `model#variant`, `opencode api` for totals, busy state and interrupt, `--standalone` for
  isolation, and a background service that survives the client. It is also where upstream is going (v1
  config still loads, and v2 is the promoted install). Supporting both doubles the parsing and permission
  work for no gain.

### 4.2 Keep the CLI JSON stream, backed by `opencode api` (not the SDK)

catherd starts detached children whose stdout goes to a file and reconciles them after an MCP restart
(src/core/spawn.ts:46-50, src/core/reconcile.ts). The CLI fits that model: the v2 background service
already owns the session, so a crashed catherd loses nothing. Proposed flow:

1. Launch: `opencode run --format json -m <provider/model[#variant]> --agent <catherd-agent> [--auto]
   [--standalone] [-s <session>]`, with the **brief on stdin** (`stdinFile`), `cwd` = repo, and **`env.PWD`
   = repo**.
2. Live: tail the JSONL as today. Take `sessionID` from the first event. Count `tool_use` and `text` as
   activity.
3. Watchdog: when quiet, call `opencode api GET /api/session/active`. If the session is running, also call
   `GET /api/session/<id>/message` and check `data[0].retry`: if a retry is pending with
   `provider.quota`/`provider.rate-limit`, finish early as `limit` (interrupt it). If the call fails,
   count failures and stop treating the session as busy after N of them.
4. Finish: `GET /api/session/<id>` gives `cost`, `tokens` (input, output, reasoning, cache.read →
   `cached`) and `outcome`. Status mapping: exit 0 and outcome `succeeded` → `ok`; `error.type`
   `provider.quota|provider.rate-limit` → `limit`; `aborted` after our own interrupt → `timeout` or
   `interrupted`; `aborted` with no interrupt from us → `failed` with "permission rejected: <action>
   (<resources>)", taken from the stderr line `permission requested: … auto-rejecting`; anything else →
   `failed`, using `error.message`.
5. Interrupt: `opencode api POST /api/session/<id>/interrupt`, as today, **then** kill the client. Or send
   SIGINT to the client, which interrupts server-side itself (exit 130).

Why not `@opencode/client` now: it is labelled "private generation target", the HTTP API is
"experimental", and it would make catherd hold a long-lived SSE connection inside the MCP process, which
cuts against the detached-child design. Revisit if catherd ever needs streaming progress. `opencode api`
already gives typed JSON through the same API with auth handled. (A middle path: create the session first
with `opencode api POST /api/session` and a location, then run `run -s <id>`. The id is then known before
the first event, which removes the `session ??=` race in `:152/:199`.)

### 4.3 Model discovery: Zen and Go only, live from opencode, cached

- Delete the models.dev ingestion for opencode (`catalog/models-dev.json`, `refreshModelsDev`,
  `trimModelsDev`, and the `loadCatalog` merge at `catalog.ts:84-93`). Replace it with
  `catherd catalog refresh`, which runs:
  1. `opencode auth list --format json` → the connected set among `opencode` and `opencode-go`. Free
     `opencode/*-free` and `big-pickle` are always available.
  2. `opencode api model.list --param location[directory]=<repo>` (retry up to about 5 times, 1-2 s
     apart, while `data` is empty: the warm-up race). Keep `providerID ∈ allowlist`, default
     `["opencode","opencode-go"]`, and let the user add providers in the profile for anyone who does use
     OpenRouter or another provider.
  3. Store `<data>/opencode-models.json`:
     `{fetchedAt, opencodeVersion, models: {"opencode-go/glm-5.3": {plan:"go"|"zen"|"free", variants:["low","high","max"], context, imageIn, toolCall, costIn, costOut, status}}}`.
- Label the plan in the TUI: **Go** (subscription quota; cost-rank it like the ChatGPT/Claude plans, cheap
  first); **Zen** (metered dollars; cost-rank by `costIn`/`costOut`); **Free** (warn that data may be used
  for training; keep it off by default for real repos).
- When a model is listed under both, e.g. `opencode-go/kimi-k3` and `opencode/kimi-k3`, prefer the Go id
  while the Go quota lasts, and use Zen as the **failover** (`profile.failover`) when Go returns `limit`.
  This fits the Go docs' own "use balance" idea and gives quota failover a real use.
- The listing does not prove entitlement (§1.4). The first dispatch error (`provider.auth`,
  `provider.no-route`) should mark the model "unavailable" in the cache and tell the user why.
- Scores: seed `treatLike` for provider-hosted copies of models catherd already scores, e.g.
  `opencode/gpt-6-sol#high → gpt-6-sol#high`, `opencode/claude-opus-5-5#high → claude-opus-5-5#high`,
  `opencode(-go)/gpt-6-luna#high → gpt-6-luna#high`. The Zen docs promise un-degraded serving, but
  UNVERIFIED that the scores carry over exactly.

### 4.4 Effort and variants

- Keep the rung format `provider/model#effort` (it is what v2 accepts). Let `effort` be one of the model's
  **discovered** `variants[].id`, or `default`, meaning no `#` suffix and the catalog default. Do not map
  names between vendors: `thinking` on minimax-m3 or `xhigh` on qwen3.8-max are passed through as they
  are.
- Validate before dispatch: an effort missing from the cached variants gets a clear catherd error that
  lists the valid ones, rather than opencode's `Variant unavailable`.
- For routing comparisons with Codex efforts, `none < minimal < low < medium < high < xhigh < max` is a
  usable order. Treat unknown names (`thinking`) as unordered.

### 4.5 Permissions and agents (never ask)

Ship three catherd agents as v2 markdown files (`mode: primary`). Install them into
`~/.config/opencode/agents/` for native mode, and into
`<data>/opencode-home/config/opencode/agents/` for isolated mode:
- `catherd-readonly` (architect, reviewer, researcher): `*:* deny`; allow `read`, `glob`, `grep`,
  `webfetch`, `websearch`; `shell` allowlist (`git status *`, `git diff *`, `git log *`, `git show *`,
  `rg *`, `ls *`, `cat *`, plus the project's test command if the profile names one); `edit` deny;
  `subagent` deny. Run with `--auto`.
- `catherd-worker` (worker, artist, writer): base policy; `external_directory` allow for the system temp
  dir; deny `shell` for `git push *`, `git commit *`, `git reset --hard *`, `rm -rf /*`; `question` deny.
  Run **with `--auto`**, so remaining asks do not abort the run. The deny rules are the guard rails.
- `catherd-full` (verifier, ui-reviewer): the `build` defaults, with `--auto`.
- Record the permission rejection or abort reason in `RunRecord.error`.
- A repo-local `.opencode/agents/` would also work, but it dirties the user's tree, and catherd tracks dirty
  files.
- UNVERIFIED: whether the background service picks up a newly written global agent file without
  `opencode reload` (`POST /api/location/reload`). Call `opencode reload` after installing the agents.

### 4.6 Tokens and cost

`GET /api/session/<id>` after the run: `costUsd = data.cost`; `tokens.input = data.tokens.input`;
`tokens.cached = data.tokens.cache.read`; `tokens.output = data.tokens.output + data.tokens.reasoning`
(or add a `reasoning` field). These are totals for the session, including the title agent's small call
(Zen notes that cheap models are used for titles). For resumed sessions (`-s`), take the delta between
the totals before and after, or sum the new assistant messages from `/message`. Go usage reports list
prices in `cost` even though the subscription pays for them. Keep that figure for budget comparison, but
label it "quota $" rather than cash (UNVERIFIED that Go sessions report non-zero `cost`).

### 4.7 Testing

1. **Fake binary** (`test/fixtures/bin/opencode`): make it a small v2 simulator.
   - `--version` prints `opencode v2.0.16`, or `FAKE_OC_VERSION=1.18.32` for the too-old test.
   - `auth list --format json` returns connected ids from `FAKE_OC_AUTH`.
   - `api model.list` and `models` serve `FAKE_OC_MODELS` (default: a trimmed copy of the real
     `v2-api-model-list` sample), and return empty once when `FAKE_OC_WARMUP=1`.
   - `run` rejects unknown flags and argv messages that start with `-` (exit 1 plus help), reads the
     message from **stdin**, and records `process.env.PWD` (not `process.cwd()`) as the directory. It
     rejects `#variant` values missing from the model's variants, with a real
     `{"type":"error","error":{"type":"provider.no-route",…}}`.
   - `api GET /api/session/<id>` returns `{data:{cost,tokens,outcome}}`; `GET /api/session/active`
     returns `FAKE_OC_ACTIVE`; `POST …/interrupt` returns `{"interrupted":true}`; a `retry` field is
     available on demand.
2. **Fixtures**: replace the hand-written JSONL with real captures, sanitized:
   `research/opencode-samples/v2-ok-simple.jsonl` (no `step_finish`), `v2-explore-tools.jsonl`,
   `v2-shell-ok.jsonl`, `v2-permission-rejected.jsonl`, `v2-interrupted.jsonl`, plus synthesized
   `provider.quota` and `provider.rate-limit` error lines in the v2 shape.
3. **Unit tests to add**:
   - v1 is refused as cli-too-old;
   - `PWD` is set to the repo;
   - the brief goes on stdin (and a brief starting with `---` works);
   - tokens come from the API;
   - quota and rate-limit map to `limit` and trigger failover;
   - a failing `api` is not "busy forever";
   - a permission abort gives a readable error;
   - variant validation;
   - discovery keeps only `opencode` and `opencode-go` and retries on an empty list.
4. **Live test** (`test/live/opencode.live.test.ts`, gated by an env flag like the codex live test): use
   **`opencode/space-bunny-free`**, which runs with **no key and $0** [verified], in a temp git repo.
   Check:
   - a JSON stream arrives with a `sessionID`;
   - `api GET /api/session/<id>` shows `tokens.input > 0`;
   - `#low` works and `#bogus` fails with `provider.no-route`;
   - a brief starting with `---` goes through stdin;
   - `PWD` is honoured;
   - the readonly agent cannot edit;
   - `POST …/interrupt` stops a `sleep 40` shell tool.

   Add an opt-in second tier that uses the user's real Zen or Go key with a cheap model (e.g.
   `opencode-go/deepseek-v4-flash#low`, `opencode/gpt-6-luna#low`) to check cost > 0 and the plan
   labels. Free models can be rate-limited, and big-pickle hung silently on v1 during this research, so
   the live test needs a generous timeout and one retry.
