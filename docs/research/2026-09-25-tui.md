# catherd TUI: audit, research and a redesign proposal

Date: 2026-09-25. Repo state: `c0479cb` (catherd-cli 0.2.1, @opentui/core + @opentui/react 0.5.12, React 19).
Method: read all of `src/tui/*` and `test/tui/*`, `docs/tui-frames.md`, and spec §8. Ran `bun test test/tui`
(108 pass, 1 fail). Drove the real binary under tmux at 80x24, 80x30 and 60x20 with an isolated
`CATHERD_HOME` and `CATHERD_CLAUDE_AGENTS_DIR`, sending real keys (`tmux send-keys`) and capturing panes.
Everything marked **(observed)** below was seen in a live terminal, not only in the code.

---

## 0. TL;DR

- Most of the "toy-like and untrustworthy" feel comes from **app-level design**, not from OpenTUI. The
  big problems: Enter saves and activates a profile from any row. Esc never goes back. There is no
  way back to the dashboard. Ctrl-C quits with unsaved work and exit code 0. At 80x24 the key hints
  are pushed off-screen. Truncation happens in the *middle* of a line, which mangles fix commands and
  prompts. Final instructions disappear when the program exits. One keypress silently removes all of a
  model's efforts.
- Keyboard handling is a set of broadcast `useKeyboard` listeners (5 components, 7 hooks) that gate
  themselves with booleans. There is no keymap registry, no consumption, no context stack, and hint
  strings are hand-typed separately from the handlers, so the two drift apart.
- **Stay on OpenTUI**, but use it properly: one root key router (or `@opentui/keymap`), pinned exact
  versions, JS-side end-truncation, `useMouse: false`, and main-screen or stdout output for anything the
  user must copy. Ink would not fix any of the problems above, and catherd is Bun-only anyway.
- Move profile editing primitives to a **non-interactive CLI** (`catherd profile set/use/new/rm/show/diff`).
  It should share one service with MCP `profile_set`. Then make the TUI a simpler, safer front-end
  with staged edits, a diff-and-confirm save, undo, and a help overlay generated from the keymap.

### A3. Information architecture

- **Screens today:** Dashboard (menu of 5 actions + status) → Profile editor (17-row left nav × detail pane)
  / Watch (run list × detail) / Setup (= `init` again). `catherd init` = intro → key → backends → matrix → done.
- **The dashboard is a menu, not a dashboard.** Two of its five items are not destinations. "Exit"
  duplicates `q`. "Refresh catalog" is a **placebo**: it calls `d.loadCatalog()`, throws the result away and
  says "Catalog reloaded." (`dashboard.tsx:152-155`), while the real refresh is `catherd catalog refresh`.
  The status block is the useful part, but it has no actions ("fix", "copy command").
- **What users actually need to do**, in order of frequency:
  1. See whether runs are healthy (live lanes, climbs, budget, landed milestones).
  2. Check that setup is OK (keys, backends, agents) and fix what is not.
  3. Occasionally change the profile: tick models or efforts per role, objective, budget, failover, isolation.
  4. Rarely create, copy, switch or delete profiles.
  The TUI puts (3) first and gives (1) a thin, fixed-height view. The spec's `watch` features
  (landed milestones stacking, `milestoneLine`, `recordLine`) exist in `watch-model.ts` but are never rendered.
- **The profile matrix mixes three kinds of controls** in one left list: 8 role toggles, scalar settings
  (objective, heavy slots, isolation) and sub-editors (budget, failover, notify). Each has different
  Space/Enter/→ semantics. The notify detail pane renders a non-interactive list (`matrix.tsx:447-460`).
- **Profile operations are hidden single letters.** `p`, `n`, `c` and `x` only appear after `?`, and they
  appear in the Editor but not in `init`'s matrix.
- **No diff or preview before save.** MCP `profile_set` returns a diff and `new_session_needed_for`, but the
  TUI shows neither. `microdiff` is already a dependency.
- **Two profile writers with different rules.** The TUI can set budget and failover. MCP `PATCH` cannot
  (`setup-tools.ts:26-41`). The TUI activates on save; MCP does not.
- **Watch reads files synchronously on the UI thread** every 2 s (up to 20 runs), and `readJev` runs on
  **every render**, including every keypress (`watch.tsx:44-60, 109`). This is input latency waiting to happen.
- `catherd --help` does not mention that bare `catherd` opens an interactive dashboard, and the bare
  command does not list `--plain`/`--reduced-motion`. Non-TTY `watch` just errors. There is no `--once`/`--json`.

### A4. Visual trust problems

- **Chrome over content.** A 3-line cat and gradient wordmark head every screen and cost 20% of an
  80x24 terminal. Nested rounded boxes, a filled pink selection bar and a surface-tinted detail pane
  make it look like a web mock-up, not a tool.
- **Whimsy replaces facts.** Spinner copy says "negotiating with Luna…" or "coaxing Sol off the keyboard" and
  gives no elapsed time or what is actually being probed. Error rows use `=x.x=` as the error marker. Run
  rows lead with a face (`=o.o= Jo...`) instead of the state word. `🐈` in the live-lane line is a 2-cell
  emoji whose width varies by terminal and font (`theme.ts:62`, `watch-model.ts:32`).
- **Inconsistent glyph grammar.** `●/○` mean "enabled" (roles, notify, models), "ticked"
  (efforts) *and* "ready/warn/missing" (status), and **warn uses the same `●` as ready**, told apart only by
  colour (`theme.ts:88-90`). Under NO_COLOR "opencode not logged in" and "Claude agents 0 linked" show the
  same filled dot as healthy rows (observed). `▸/▾`, `▶`, `→` and `⇄` are all in play. The spec's paw
  checkbox (🐾) was dropped in the code, which is right, but the spec was never updated.
- **Pink as error colour.** Errors, notes, headings, the accent and the selection all use the same pink
  (`ACCENT = "pink"`, errors `tint("pink")`), so a validation error looks like a heading.
- **Placebo and lossy UI** (placebo refresh, ctrl-c data loss, vanishing final instructions, mangled
  commands) does more damage to trust than any colour choice.

### A5. Accessibility

- NO_COLOR: `tint()` returns undefined at depth 1, which is good, but state is colour-only in places (warn vs
  ready, K10 selection falls back to bold + `▶` only). No `TERM=dumb` handling. `FORCE_COLOR`/`--no-color` are
  not supported. The theme test that checks colour depth fails under Bun 1.3.11 (`theme.test.ts:100`,
  TERM=xterm → 8 not 4). `engines` says bun ≥1.4, but the dependency on Bun's `getColorDepth` is fragile.
- `--plain`: only triggered by the flag or `TERM=linux`. It ignores `LANG`/`LC_ALL` without UTF-8. It is not
  offered on bare `catherd`'s help. Plain collapses warn into ready (`theme.ts:81-84`).
- Reduced motion: flag only. It does not respect `CATHERD_REDUCED_MOTION`/`CI`, and does not stop the
  2 s watch reflow. The intro still runs by default, and "Setup" replays it.
- Screen readers: alternate screen + full redraws are hostile. There is no main-screen/linear mode for
  `init`, no `--no-input`, and no scriptable equivalent (clig.dev: every prompt should have a flag [11]).

### A6. Code structure and testability

- State is scattered across `useState` in 4 components (the matrix alone has 7 pieces), with a
  union-typed `mode` that renders entirely different trees. Parent/child communicate through 10 callback
  props (`onChange`, `onCatalog`, `onSubmit`, `onQuit`, `onKey`, `onToggleHelp`, `active`…).
- Key handling is written inline in handlers, the help text is separate hand-written strings, and nothing
  ties them together (K9).
- Side effects (fs writes, network, `renderer.destroy`, `process.exitCode`) are called straight from key
  handlers and render bodies, although deps injection already exists (`EditorDeps`, `WatchDeps`, …).
- `matrix-model.ts` is a good pure core (tests cover it). Extend that pattern: a pure
  `reduce(state, command)` and a pure `route(contextStack, key) → command`.
- Tests: 109 tests, good coverage of behaviour, but timing-based (`tick(30)` sleeps between keys,
  `helpers.ts:25-56`). They trigger React `act(...)` warnings, never test same-tick bursts or paste into
  inputs, and have no golden frames: `tui-frames.md` is eyeball-only and stale.
- Dead code: `milestoneLine`, `recordLine`, the `paw` and `swap` glyphs.

## Part B: Research

### B1. Conventions of well-regarded developer TUIs

| App | Quit | Help | Navigation | Filter / palette | Confirm | Notes |
|---|---|---|---|---|---|---|
| lazygit [1] | `q`, `ctrl+c` | `?` keybindings menu (context-aware) | arrows + `j/k`, `h/l` panels, `[`/`]` tabs, `<`/`>` + Home/End top/bottom, `,`/`.` page, PgUp/PgDn, `ctrl+u/d` | `/` search | Enter confirms, Esc cancels; `z`/`Z` undo/redo | status panel, command log `@` |
| k9s [2] | `:q`, `ctrl+c` | `?` shows active mnemonics | vim + arrows | `:` command mode (`:pod`), `/` regex filter, `/!` inverse | `ctrl+d` delete *with* confirm; `ctrl+k` kill without | Esc "bail out of view/command/filter mode" |
| Claude Code [3] | `ctrl+d` (press twice within 800 ms) | `?` shows shortcuts for your environment | Select context: Down/`j`/`ctrl+n`, Up/`k`/`ctrl+p`, PgUp/PgDn, Home/End, Enter accept, Esc cancel | `/` commands | Confirmation context: Enter yes, Esc no; **removed bare `y`/`n` defaults in v2.1.280** because letters fired on dialogs that never showed them | contexts (Global, Chat, Confirmation, Select, Settings…) in `keybindings.json`; `ctrl+c`/`ctrl+d` reserved |
| Codex CLI (ratatui) [4][5] | `ctrl+d` twice / `/quit`; `ctrl+c` interrupts, 2nd quits | `?` overlay | contexts: global, chat, composer, pager, list, approval | `/` commands; `/keymap` rebinding | approval: Enter/Esc | `ctrl+u` wipes input line |
| opencode (OpenTUI) [6] | `ctrl+c`, `ctrl+d`, `<leader>q` | help unbound by default | leader `ctrl+x` (2 s timeout) | **`ctrl+p` command palette** | Esc interrupts | all keys configurable in `tui.json` |
| charm bubbles/help [7] | — | ShortHelp one line, `?` toggles FullHelp (grouped columns) | — | — | — | help is **generated from the key.Binding registry**; disabled bindings hidden; width-aware "…" |
| clig.dev [11] | Ctrl-C exits fast; second Ctrl-C forces | — | — | — | y/n for risky; `--force` non-interactive; type-the-name for severe | TTY check, `--no-input`, NO_COLOR/TERM=dumb, no animation off-TTY |

Common rules that trustworthy TUIs follow:
1. **One key registry drives both behaviour and help.** Bubbles `KeyMap`, Claude Code contexts, Codex
   contexts, `@opentui/keymap` `getActiveKeys()` [9] all do this. Footer = short help. `?` = full, grouped,
   context-aware help.
2. **A context stack** (global → screen → pane → dialog/input). The innermost context consumes the key.
   Text inputs own all printable keys.
3. **Esc always backs out one level. `q` quits from top-level views only. Ctrl-C is reserved** (cancel, and
   quit on the second press). Destructive quits need a double press or a confirmation.
4. **Enter = primary action on the focused item. Space = toggle.** Saving is explicit (`ctrl+s`/`w`) or
   automatic with undo, never a side effect of Enter.
5. **Arrows *and* vim keys**, plus PgUp/PgDn, Home/End (`g`/`G`) in every list.
6. **Confirmations** show explicit choices. Enter picks the highlighted one, Esc cancels, and destructive
   dialogs default to Cancel. No "any other key cancels".
7. **A palette or command mode** (`:` in k9s, `ctrl+p` in opencode) gives discoverability without memorising keys.
8. **Colour restraint.** Colour carries state (green/amber/red), one accent marks focus, and everything else
   is default fg or dim. Glyph + word, never colour alone.

### B2. Framework options (Bun/TypeScript, 2026)

**OpenTUI** (`@opentui/core` + `react`/`solid`, anomalyco, ~13k★) [6][10][12]
- Production: powers opencode ("millions of users") [10]. There were 10 releases between 2026-08-12 (0.5.2) and 2026-09-22 (0.5.12) [12], so it moves fast on a 0.x line.
- Keyboard: global `renderer.keyInput` listeners run before the focused renderable. `KeyEvent.preventDefault()`
  / `stopPropagation()`. Component-level `keyBindings`/`keyAliasMap`. Kitty protocol. **No automatic
  Tab traversal** [13]. `@opentui/keymap` adds scoped layers, named commands, sequences, focus-aware
  routing and `getActiveKeys()`/`getCommands()` for help bars, with a React provider [9]. Core also ships
  `buildKeyBindingsMap`/`keyBindingToString` (`lib/keybinding.internal.d.ts`), which catherd does not use.
- Known issues: `useKeyboard` is a broadcast emitter with no consumption, so global shortcuts fire in text
  fields and focus guards updated in effects race same-tick bursts and paste [8]. Kitty protocol is always
  pushed, which corrupts input on some terminals (opencode #51086) [14]. Teardown races with Ctrl-C [15].
  The React binding gets less production mileage than Solid (opencode uses Solid) [16]. Truncation is
  middle-ellipsis (observed). The defaults are alt-screen + mouse capture.
- Runtime: Bun ≥1.3 (Node needs experimental FFI) [16]. catherd is already Bun-only (`bin: src/cli.ts`, `engines.bun`).
- Testing: `@opentui/react/test-utils` `testRender` + `@opentui/core/testing` mock input, `captureCharFrame`
  (already used).

**Ink 7** (React, JS renderer) [16][17]
- Mature and stable. Used by Claude Code, Gemini CLI, Copilot CLI and Wrangler [16]. Ink 7 needs Node 22 and React 19.2 [17].
  `useFocus` with automatic Tab cycling, `useInput`, `ink-testing-library` (`lastFrame`, `stdin.write`) [18].
- Costs: full view rewrite (~1.6k LOC of TSX). A JS renderer throttled to 30 fps is fine for catherd.
  None of catherd's real problems (K1-K20, L1-L8) are framework bugs. opencode itself scoped an Ink
  rewrite and closed it as "not planned" [19].

**Others**: ratatui/bubbletea are excellent but not TS. blessed/neo-blessed are unmaintained.
`@clack/prompts`-style linear prompts suit `init` (scrollback-friendly, trivially scriptable) but would be
a second UI stack.

**Verdict: stay on OpenTUI**, with guardrails:
1. Pin exact versions (`0.5.12`, no caret) and upgrade deliberately. Add a smoke test per upgrade.
2. **One root key router.** Either adopt `@opentui/keymap`, after a half-day spike of its React provider,
   or write a ~150-line pure router with the same shape (contexts, commands, bindings, `activeKeys()`).
   Only the root calls `useKeyboard`. Inputs get keys by ownership, not by boolean gates.
3. `createCliRenderer({ exitOnCtrlC: false, useMouse: false })` and handle Ctrl-C in the router.
   Consider `useKittyKeyboard: null` behind an env opt-out.
4. Never use native `truncate`. Pre-truncate in JS with `string-width` at the end (`…`), and never truncate
   commands: wrap them.
5. Anything the user must keep (plugin commands, save summary, fix commands) is printed to stdout after
   the renderer is destroyed, or rendered in `main-screen` mode. Spike `screenMode: "main-screen"` for `init`.
6. Revisit Ink only if catherd must run under plain Node/npx without Bun.

### B3. CLI vs TUI for profile editing

Yes: make the primitives non-interactive, and let the TUI and MCP call the same service.
The spec already says one writer should keep TUI and conversation in sync (§11). Today there are two writers with different rules (K2, A3).

```
catherd status [--json]                       # setup + active profile + runs (safe off-TTY)
catherd doctor                                # ideas.md backlog item; exit code = health
catherd profile list [--json]
catherd profile show [name] [--json]
catherd profile use <name>                    # activate (separate from save!)
catherd profile new <name> [--from <name>]
catherd profile rm <name> [--yes]             # non-TTY requires --yes (clig.dev)
catherd profile set [--profile <n>] key=value …   # objective=speed roles.reviewer.enabled=false
                                              #   budget.usd=5 harness.codex.isolated=true
                                              #   failover.gpt-6-sol#medium=openrouter/…#high
catherd profile tick|untick [--profile n] <role> <model>#<effort>
catherd profile edit [name]                   # $EDITOR on JSON → validate → diff → confirm
catherd profile diff|validate [name]
catherd runs [--json] ; catherd watch --once [--json]
```
Every command prints the same diff and "new Claude Code session needed for …" block that `profile_set`
returns, and supports `--dry-run`. One `ProfileService.apply(name, patch, {activate})` backs the CLI,
MCP and TUI. Extend the MCP `PATCH` with budget/failover while doing this. The TUI command palette
shows the CLI equivalent of each action, which teaches the CLI and builds trust.

## C. Recommended TUI design

### C1. Screens (one app, three tabs, plus the separate `init` wizard)

| Tab | Purpose | Contents |
|---|---|---|
| **1 Status** (default for bare `catherd`) | "Is everything OK, and what do I fix?" | Setup checks (Jev key, codex, opencode, Claude agents, plugin), each with state word + fix command (full, wrapped, copyable with `y`). Active profile summary. Most recent 5 runs with state. |
| **2 Profiles** | Inspect and edit profiles safely | Profile switcher row. A single tree: ROLES (role → models by backend → efforts), ROUTING, HARNESS, BUDGET, FAILOVER, NOTIFY. A detail/status line at the bottom. Staged edits, diff-confirm save, undo. |
| **3 Runs** | Watch runs | Run list (state word first, title, repo, live/done/landed, age). Enter opens the run detail: live lanes table (role, rung, elapsed, state), climbs, Jev decisions, budget bar, landed milestones. Auto-refresh with a visible "updated 2s ago" and `p` pause. |

Overlays (dialogs): Help (`?`), Command palette (`:` / `ctrl+p`), Save (diff + choices), Confirm (delete,
discard), Pickers (treat-like, failover stand-in), Value editor (budget numbers, heavy slots, profile name).

Responsive rules: ≥ 110 cols = two panes (tree + detail). 80-109 = one pane plus a 1-line detail bar.
< 80 = one pane, abbreviated footer ("? help"), no borders. Chrome budget at 80x24: header 1 + tabs 1 +
rule 1 + footer 2 = 5 rows, leaving **19 content rows** (today about 6).

### C2. Navigation model

- **Context stack:** `global` → `tab:<name>` → `pane:<name>` → `overlay:<name>` → `input`. The router walks from
  the top of the stack down, and the first binding that matches **consumes** the key. When an `input` is on top,
  it owns all printable keys. Only `esc`, `enter`, `tab`, `ctrl+c` and the readline chords reach it.
- **Esc** pops one level: close overlay → clear filter → collapse node → leave run detail → (top-level: nothing).
- **q** quits from any tab when no overlay/input is open. With unsaved changes it opens the "Discard changes?" confirm.
- **Ctrl-C**: cancels the current input or overlay. At top level it quits if clean. If dirty, the first press
  shows "Unsaved changes. Press ctrl+c again to discard and quit" (1.5 s window), as Claude Code and Codex do.
  Exit code 130 on interrupt, 0 on a clean quit.
- **Tabs:** `1`/`2`/`3`, or `[`/`]` for prev/next. **Tab/Shift-Tab** moves focus between panes, dialog buttons and form fields.
- **Edits are staged** in a draft per profile. The header shows `modified (n)`. Nothing touches disk until
  **Save** (`ctrl+s`), which opens the diff dialog: [Save] [Save & make active] [Cancel]. Activation
  is also its own command (`a`, with a confirm). `u` undo, `ctrl+r` redo (edit history per draft).
  Treat-like choices are staged too (fixes K6).

### C3. Keymap

shows the pane's top 5-6 plus `? help`. `?` shows everything active, grouped. Tests guarantee no duplicate
key within a reachable context stack and help text for every binding.

### C4. Visual language

- **Header (1 line):** `catherd 0.2.1  profile default ● active · modified (2)            =^.^=  ? help`.
  The cat *face* stays as a compact, mood-bearing status glyph (brand kept, 5 columns). The 3-line mascot
  and gradient wordmark appear only on `init`'s welcome, on empty states ("No runs yet") and in `--version`.
- **Tabs (1 line):** `1 Status   2 Profiles   3 Runs`. The active tab is bold + accent underline (reverse video under NO_COLOR).
- **No outer box.** Use thin rules (`─`, `-` in plain) under the tabs and above the footer. Boxes only for dialogs.
  Section headings are uppercase dim bold, not accent.
- **Colour:** default fg for content, dim for secondary, **one accent (ginger) for focus/selection only**,
  semantic green/amber/red for state only. Errors are red, never the accent. No background fills except the
  selected row (subtle accent-tinted bg; reverse video under NO_COLOR). No gradients in working views.
- **Glyph grammar (Unicode → plain):** checkbox `[x]`/`[ ]` (same in both). Radio `(•)`/`(*)` and `( )`.
  Expand `▸`/`▾` → `>`/`v`. Selection `›` → `>`. State **glyph + word**: `✓ ready` / `! warning` / `✗ missing` /
  `● live` / `◌ waiting` → `ok`, `!`, `x`, `*`, `.`. No emoji anywhere.
  Scroll hints: `↑ 3 more` / `↓ 11 more`.
- **Copy:** facts first ("probing codex --version… 1.2s"). Herding lines may follow a fact in a spinner,
  are off under reduced motion, and are never the only text. Runs lead with a state word: `live`,
  `done`, `failed`, `paused`. The face is optional decoration after the facts.
- **Truncation:** end-ellipsis only, computed in JS. Identifiers (model ids, commands, paths) are never
  truncated in detail views; they wrap.
- **Spec change:** amend §8.4. Mascot on welcome/empty states only, `[x]` checkboxes instead of paws, and
  "Fit: every screen works at 80x24, including the footer".

### C5. Code structure

```
src/tui/
  app.tsx          root: renderer options, <KeyRouter>, tab host, overlay host, exit handling
  keymap.ts        registry: contexts, commands, bindings, help text (pure data)
  router.ts        route(stack, KeyEvent) → Command | null  (pure; normalizes name/shift/ctrl/kitty)
  state.ts         AppState + reduce(state, cmd) → { state, effects[] }  (pure; drafts, history, dialogs)
  effects.ts       runs effects via injected services (ProfileService, probes, runstore, clipboard)
  services/profile.ts  shared with MCP profile_set and `catherd profile …`
  views/…          pure views: StatusView, ProfilesView, RunsView, RunDetail, Help, Palette, dialogs
  widgets/…        List/Tree (virtualized, scroll hints), Footer (from activeKeys), TextInput, Dialog
  text.ts          truncateEnd(width), wrap, glyph table (plain/unicode), state words
```
Runs data is polled off the render path (async fs, memoised by mtime), so the render never touches the disk.

### C6. Testing approach

1. **Router unit tests** (pure). A table of `(contextStack, key) → command`. A test fails on any duplicate key
   within one reachable stack, and on any binding without help text. An "input owns printable keys" matrix
   types every global shortcut into every input (the interference matrix from [8]).
2. **Reducer unit tests** (pure). Scripted command sequences → state. Undo/redo, staged treat-like,
   dirty tracking, "Save and make active" vs "Save", delete guards.
3. **Golden frames** with `testRender` + `captureCharFrame` + `bun test` `toMatchSnapshot()`. Every
   screen × {80x24, 100x30, 120x40} × {unicode, plain} × key states (empty, error, dirty, dialog open).
   Generate `docs/tui-frames.md` *from* the snapshots (a script), so it cannot go stale.
   Assert invariants on every frame: the footer is visible on the last row, the plain frames are pure
   ASCII, no line exceeds the width, and no `...` appears in the middle of a token.
4. **Keypress scenario tests** through the mock keyboard, using a deterministic flush (`await
   renderer.idle()`/`act`) instead of `tick(30)`. Include same-tick bursts (`typeText("q?/jk")` into an input)
   and paste. Cover the critical flows: edit → ctrl+s → dialog → Save; ctrl+c dirty double-press; Esc
   ladder; delete confirm defaults to Cancel.
5. **PTY smoke test** (CI, optional): tmux or `script` runs `bun src/cli.ts` at 80x24 with isolated
   `CATHERD_HOME`/`CATHERD_CLAUDE_AGENTS_DIR`, sends `2 j space ctrl+s enter q`, and checks the exit code, the
   file diff, and that init's plugin commands are in stdout after exit. This is the harness used for this
   audit, and it caught L1, L3 and L8, which the unit tests miss.
6. **Env tests**: NO_COLOR frames contain no SGR colour codes. `TERM=dumb`/`--plain` → ASCII.
   `--reduced-motion` → no timers (fake clock). Do not depend on Bun's `getColorDepth` quirks. Wrap it.

### C7. Suggested order of work

- **Phase 0, quick wins (≈1 day, no redesign):** `exitOnCtrlC:false` + dirty-aware Ctrl-C and exit 130.
  Enter no longer saves (bind `ctrl+s`). Esc returns to the dashboard. Shrink the chrome so the footer
  fits at 80x24. JS end-truncation. `useMouse:false`. Print init's plugin commands and save summaries
  to stdout after exit. Remove the placebo "Refresh catalog". Add j/k/g/G/PgUp/PgDn. Space on a model row only
  expands. Distinct warn glyph. Stage treat-like.
- **Phase 1:** keymap registry + router + reducer. Help overlay + generated footer. Golden snapshots.
- **Phase 2:** `ProfileService` shared by MCP/CLI/TUI. `catherd profile …`, `status --json`,
  `watch --once`. Tabs IA, save-diff dialog, undo, the Runs detail with milestones.
- **Phase 3:** visual pass per C4, amend spec §8.4, regenerate frames, and a PTY smoke test in CI.
