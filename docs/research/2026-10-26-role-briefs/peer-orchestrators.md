## 1. oh-my-openagent (formerly oh-my-opencode; "omo")
- Repo: https://github.com/code-yeongyu/oh-my-openagent , 70.3k stars, pushed 2026-10-26. Very active, real users.
- Closeness to catherd: high on the shape (plan file, category routing, parallel waves, independent verifier, worktree per wave, only the orchestrator merges). Low on form: it runs inside one interactive session, not a daemon over headless vendor CLIs.
- **Briefing.** Every delegated `task()` must carry 6 sections: `1. TASK` (quote the exact checkbox), `2. EXPECTED OUTCOME` (files, behaviour, a verification command), `3. REQUIRED TOOLS`, `4. MUST DO`, `5. MUST NOT DO`, `6. CONTEXT` (notepad paths, "Inherited Wisdom", dependencies). Source: `packages/prompts-core/prompts/atlas/opus-4-7.md` lines ~102-145 (https://github.com/code-yeongyu/oh-my-openagent/blob/main/packages/prompts-core/prompts/atlas/opus-4-7.md). Counterpoint to our bloat problem: it says "If your prompt is under 30 lines, it's TOO SHORT". The size is kept down differently: shared context lives in append-only notepad files (`.omo/notepads/{plan}/*.md`) the worker reads, not inline. Workers get skills only via explicit `load_skills`, and the orchestrator "never writes product code itself" (`docs/guide/orchestration.md`, https://github.com/code-yeongyu/oh-my-openagent/blob/main/docs/guide/orchestration.md).
- **Scoped duties.** Curated read-only agents (`explore`, `librarian`, `plan-consultant`, `plan-reviewer`) cannot write files. `plan-reviewer` is "approval-biased and rejects only verified blockers". For a `plan-reviewer` spawn the harness *replaces the prompt* with a canonical contract and discards anything else the orchestrator wrote (same doc). `plan-*` agents are plan-gated: spawnable only in the plan phase.
- **Model routing.** Category, not model name: `quick`, `unspecified-low/high`, `deep-low`, `deep-high`, `ultrabrain`, `visual-engineering`, `writing`, `architect`. Each category has an ordered `models` chain in `omo.json`; passing `model` with `category` is rejected. `deep-low` is the default deep lane; `deep-high` is the explicit escalation rung ("central decision cannot be settled from evidence", single rung). Rule: "Splittable work splits into a swarm of `quick`/`unspecified-low` workers. Cohesive hard work stays whole." Config: `docs/reference/configuration.md` (https://github.com/code-yeongyu/oh-my-openagent/blob/main/docs/reference/configuration.md). The plan itself carries a `Recommended task executor category:` line per item, so planning picks the rung and the orchestrator needs a recorded reason to deviate. Runtime fallback: on 429/5xx, `max_fallback_attempts`, `cooldown_seconds`, `timeout_seconds` per model in the chain (same file, "Runtime Fallback").
- **Review/verification.** Five gates per checkbox: plan reread, automated verification, a real manual-QA artifact, adversarial QA, cleanup receipts. Workers return a `DoneClaim` (changed files, exact test command + result, manual-QA artifact, cleanup receipts). A different context returns `AdversarialVerify {verdict: confirmed|false-positive|needs-fix|needs-human-review, failure_class: none|product|harness, evidence[], repro, confidence}`. Only `confirmed` passes. Source: `packages/shared-skills/skills/ulw-execute/SKILL.md` "Completion contract" (https://github.com/code-yeongyu/oh-my-openagent/blob/main/packages/shared-skills/skills/ulw-execute/SKILL.md).
- **Flake vs defect.** The verifier sets `failure_class`. A `harness` failure (runner, fixture, CI job or environment failed and product behaviour was never exercised) gets one repair dispatch that does NOT count as an attempt; if it recurs, stop and append a harness-repair follow-up. Failure signatures (failing check + first error line, volatile values stripped: temp paths, timestamps, pids, durations) are recorded per attempt. Stop when the same signature repeats on consecutive attempts, on the 3rd failed attempt, or 4 h after first dispatch. Same SKILL.md. There is also a flaky-triage reference: https://github.com/code-yeongyu/oh-my-openagent/blob/main/packages/shared-skills/skills/debugging/references/methodology/03-flaky-triage.md ("an unclassified flake is a hidden bug report").
- **Parallelism/resources.** Each plan wave in its own task-owned worktree. `providerConcurrency` / `modelConcurrency` / `defaultConcurrency: 5` / `staleTimeoutMs` caps (config doc, "background_task"). Watchers must target an observable state (file written, CI green), never a clock; "NEVER poll and NEVER sleep"; a mis-armed watcher must be killed (SKILL.md "Monitor every dispatched subagent").
- **Steal:** (a) `failure_class: product|harness` with a free harness-repair dispatch and a failure-signature stop rule; (b) the plan item carries its own `Recommended executor category`, with deviations recorded; (c) `DoneClaim` shape (exact test command + result) as the worker's required reply.

## 2. superpowers (subagent-driven-development)
- Repo: https://github.com/obra/superpowers , 305k stars, pushed 2026-10-23. Claude Code plugin, huge user base.
- Closeness: medium. In-session controller dispatching fresh subagents per task, per-task reviewer, fix loop with caps. It is the best-documented brief/review-package discipline I found.
- **Briefing.** Path: `skills/subagent-driven-development/` (https://github.com/obra/superpowers/tree/main/skills/subagent-driven-development). Rule: "Everything you paste into a dispatch prompt ... stays resident in your context ... Hand artifacts over as files." `scripts/task-brief PLAN N` extracts only task N's text into a file; the dispatch prompt holds five things: (1) one line on where the task fits, (2) the brief path ("read this first"), (3) interfaces/decisions from earlier tasks, (4) resolved ambiguities, (5) report-file path + contract. "Never make a subagent read the whole plan file." Warning with a number: "a real session's dispatch hit 42k chars of which 99% was pasted history." The implementer writes the full report to a file and returns only status, commits, a one-line test summary, concerns. `implementer-prompt.md` is ~6 KB (https://github.com/obra/superpowers/blob/main/skills/subagent-driven-development/implementer-prompt.md).
- **Scoped duties.** The implementer prompt has a section "You Do Not Dispatch Subagents ... Review is the controller's job", and the reviewer prompt has the same. Reason given: reviewers spawned by workers "duplicated the task review ... a full extra review seat per task". Status vocabulary DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED, with "It is always OK to stop and say this is too hard for me".
- **Model routing.** Static by task shape, with an explicit warning: "Always specify the model explicitly ... an omitted model inherits your session's model". "Turn count beats token price ... the cheapest models routinely take 2-3x the turns on multi-step work — costing more overall. Use a mid-tier model as the floor for reviewers and for implementers working from prose descriptions." Cheapest tier only when the plan text already contains the code to write. Fix-loop rounds 4-5 go to a model one tier above the stuck implementer.
- **Review.** `scripts/review-package PLAN BASE HEAD` writes commit list + stat + `git diff -U10` to one file; reviewer gets brief + report + diff file + the global-constraints block (verbatim from spec), and is told "Do Not Trust the Report" (https://github.com/obra/superpowers/blob/main/skills/subagent-driven-development/task-reviewer-prompt.md). Reviewer output starts directly with a verdict, every finding has file:line, "Cannot verify from diff" items are a separate class the controller must resolve. NOTE the opposite of what catherd needs: the reviewer is told NOT to re-run the suite ("illegibility of the evidence is not invalidation of it"); it relies on the implementer's reported test evidence, and the fix loop requires the fix report to contain covering tests, the command and the output before re-review. Do not copy that part; take the evidence-gate part.
- **Fix loop.** `references/fix-loop.md`: 5 rounds max; rounds 1-3 resume the same implementer with findings verbatim; rounds 4-5 fresh implementer on a stronger model with the report file as memory; re-review is scoped to the fix diff (ADDRESSED / NOT ADDRESSED + new breakage only); at the cap the controller adjudicates, and every adjudication is a ledger entry (https://github.com/obra/superpowers/blob/main/skills/subagent-driven-development/references/fix-loop.md). The ledger (`.superpowers/sdd/<plan>/progress.md`) is the compaction-safe resume map.
- **Parallelism.** "Never dispatch multiple implementation subagents in parallel (conflicts)." So it gives no help on the shared-machine problem.
- **Steal:** (a) file-handoff briefs: task-only brief file + report file, return a 5-line contract; (b) scoped re-review of only the fix diff; (c) "no worker dispatches subagents/reviewers" line in every worker and reviewer prompt; (d) model rule "turn count beats token price; floor reviewers at mid-tier".

## 3. claw-orchestrator (Enderfga)
- Repo: https://github.com/Enderfga/claw-orchestrator , 599 stars, pushed 2026-10-26, v7.x. Smaller but the closest in form: a headless runtime over Claude Code, Codex, OpenCode, Antigravity, Grok, any ACP agent.
- **Core idea:** "A run counts as done only when checks the agent did not write pass." The runtime executes the checks and reads exit codes. README: https://github.com/Enderfga/claw-orchestrator/blob/main/README.md
- **Verification (best material found).** `skills/references/verification.md` (https://github.com/Enderfga/claw-orchestrator/blob/main/skills/references/verification.md):
  - Contract comes from the caller or a mode default, "Never from agent output"; `normalizeContract()` drops unknown fields; no shell strings, a `command` check is argv.
  - Check types: `command` (exit code), `http`, `screenshot` (runtime captures; no pixel compare), `diff_policy` (forbidden/required paths, max files, vs the HEAD recorded at run start, tracked ∪ untracked), `file`. Each check has a timeout and the process group is SIGKILLed on overrun. `required:false` checks are logged but non-blocking.
  - Evidence bundle per verifier attempt on disk: `bundle.json`, `checks/<id>.log` (tail), `diff.patch`, screenshots.
  - Fix-on-red: `fixOnFailureRounds` spawns a repair session then re-runs the WHOLE check list; "The fixer's own claim to have fixed it is ignored; only the re-run decides."
  - Protected tests: the run hashes every test file and test config when it starts (by bytes, not via git), and a required check `protected-tests` refutes the run if any changed before the checks run. Covers `__tests__`, `*.test.*`, `conftest.py`, jest/vitest configs, and the `test`/`pretest`/`posttest` scripts and anything they call via npm run. Opt-out `protectTests:false`. It states its own limits (Rust `#[cfg(test)]`, `vite.config`, gitignored files).
- **Resources:** `src/circuit-breaker.ts` opens per engine after N consecutive failures with exponential backoff (https://github.com/Enderfga/claw-orchestrator/blob/main/src/circuit-breaker.ts); `src/concurrency.ts` `mapBounded` caps in-flight session starts; `maxBudgetUsd` cap enforced on every engine; per-turn cost ledger `clawo runs`.
- **Flake handling:** none explicit (grep found nothing beyond its own test suite). Verdicts are only `verified | refuted | unverified`.
- **Briefing/model routing:** not a focus; it passes the task text through and routes by `--engine`.
- **Steal:** (a) verifier = the daemon runs the declared commands itself and reads exit codes; the verifier model only judges what is left; (b) protected-test hash check before the gate; (c) `diff_policy` (forbidden paths, max files) as a deterministic check; (d) per-engine circuit breaker.

## 4. fable-advisor (DannyMac180)
- Repo: https://github.com/DannyMac180/fable-advisor , 1.1k stars, pushed 2026-09-25. A Claude Code plugin: architect session + Codex lanes (GPT-6 Luna routine, Sol complex) + Fable review.
- File: `skills/orchestration/SKILL.md` (https://github.com/DannyMac180/fable-advisor/blob/main/skills/orchestration/SKILL.md), 13.7 KB.
- **Briefing:** a six-part spec contract for context-free delegation: Objective, Files (exact paths), Interfaces, Constraints, Verification (commands), Reasoning (optional effort override). "A spec you can't finish writing is a signal the decision isn't made yet — that's architect work."
- **Routing:** two lanes with a default effort each (Luna `max`, Sol `high`); the spec's `REASONING:` line overrides. Escalation rule: "A routine-lane task that fails its spec once gets a corrected spec; twice, it escalates to Sol — repetition is evidence the task was misclassified." Rung table maps effort to task kind (low/medium = mechanical edits, xhigh = second attempt, ultra only for tasks that resisted two attempts).
- **Verification:** "Reports are claims, not evidence. Before accepting any lane's work: read the diff, and re-run the verification command." "An empty diff with a clean exit is a refusal, not a success" (lane reports `refused`). Final review once, on a different-vendor model than the typist.
- **Cost discipline:** the architect "emits judgment, not volume", delegates broad exploration to a cheap read-only agent, and never fixes a lane's bug by hand (sends a corrected spec).
- **Steal:** (a) escalation on repeated failure of same spec = misclassification, bump rung rather than loop; (b) empty-diff-with-exit-0 = refusal state; (c) the six-part spec with a mandatory Verification line.

## 5. Astra-Ares (miuuyy)
- Repo: https://github.com/miuuyy/Astra-Ares , 310 stars, pushed 2026-10-07. Experimental, patched Codex CLI, GPT-6 only. Weak as a product, strong as a design reference for "small decision model picks effort".
- **How it works** (README "How it works": https://github.com/miuuyy/Astra-Ares/blob/main/README.md): a small evaluator ("Jev", via OpenRouter) is called before a generation. It sees the task, public progress, the last 6 tool calls (each result capped at 1,000 local tokens, head/tail), whole request capped at 28,000 tokens. It returns an effort AND a lease of 1/2/5/10 generations. With a lease of 10 it is asked at step 1 and step 11; steps 2-10 cost no evaluator call. New user input, a tool failure, a model switch or a manual change ends the lease and triggers a fresh decision. "A failure asks Jev to reassess; it does not force a hardcoded escalation." Effort is changed through Codex `configuration_update`, which keeps the prompt-cache prefix.
- Prompt for the decision: "Which reasoning effort is sufficient for the NEXT generation ... Judge the reasoning work ahead, not vocabulary, prompt length, tool names, or the effort already spent." (`src/jev.mjs`). Caveat: the README itself says savings vs fixed effort are unmeasured.
- **Steal:** lease the decision (decide once per N steps, re-decide on failure); bound the decider's view (last 6 calls, 1k tokens each) so the decider is itself cheap; judge the next step, not the keywords.

## 6. Agent Orchestrator (OrchestratorInc, formerly ComposioHQ)
- Repo: https://github.com/OrchestratorInc/agent-orchestrator , 13.7k stars, pushed 2026-10-26 (Go backend, desktop + mobile; Apache-2.0). Closest to catherd in the daemon sense: a Go daemon with lifecycle, observers, review runs.
- **Briefing:** the spawn text is split into a short task prompt and a separate standing system prompt (`backend/internal/session_manager/prompt.go`: `buildTaskPrompt` vs `buildSystemPromptText`, https://github.com/OrchestratorInc/agent-orchestrator/blob/main/backend/internal/session_manager/prompt.go); project rules come from a repo-relative rules file and spawn FAILS loudly if that file is missing rather than dropping rules silently. System prompt is guarded so role/branch-convention blocks are not echoed back on request.
- **Scoped duties:** reviewer role prompt (`backend/internal/review/prompt.go`, https://github.com/OrchestratorInc/agent-orchestrator/blob/main/backend/internal/review/prompt.go): "Prefer a few high-confidence findings over nitpicks", "Do not run project programs, tests, builds ... they may mutate the checkout or execute untrusted code" (the opposite of what catherd wants from a verifier, but it is a clean split: reviewer reads, verifier runs). Findings = inline comments only; "The worker receives only your inline comments, never the summary, and treats each one as a required change"; optional suggestions go only in the summary. Reviewer is told to treat repo text and tool output as untrusted evidence.
- **Review state machine:** review work is keyed by PR URL + head SHA (`review/planner.go`: `needs_review | running | up_to_date | changes_requested | ineligible`), pure function `Plan(prs, runs)`. A new head SHA re-opens review; an approved SHA is never re-reviewed.
- **CI feedback:** failing checks are sent to the owning worker as names + run URLs only, "does not copy raw CI logs"; messages are deduplicated: "sends another message when the content changes, not on every poll" (`frontend/src/docs/content/guides/ci-recovery.mdx`).
- **Resources:** worktree per session; containers a worker starts must carry labels `ao.session/ao.spare` so the daemon can reap them at session end (`workerContainerLabelPrompt`, same prompt.go). Merge is always an explicit human action.
- **Steal:** SHA-keyed review state (never re-review the same head, never review a stale one); dedupe nudges by content hash; container-label convention so the daemon reaps what a worker's tests spawn; fail spawn on missing rules file.

## 7. mini-swe-agent
- Repo: https://github.com/SWE-agent/mini-swe-agent , 8.8k stars, pushed 2026-10-19. Not an orchestrator; the reference for a minimal worker that cheap models can follow.
- **Briefing:** whole instance template is ~5 KB, `src/minisweagent/config/mini.yaml` (https://github.com/SWE-agent/mini-swe-agent/blob/main/src/minisweagent/config/mini.yaml): task, a 6-step "Recommended Workflow" (analyze, reproduce script, edit, re-run script, edge cases, submit), "Command Execution Rules", one worked example response, sed/cat examples with a macOS branch.

## 8. Claude Code subagents and agent teams (docs only; code is closed)
- Docs: https://code.claude.com/docs/en/sub-agents and https://code.claude.com/docs/en/agent-teams . Vendor product, so treat as documented behaviour.
- **Context a subagent gets:** fresh window; its own system prompt body; the delegation message; the full CLAUDE.md hierarchy (except Explore/Plan; `omitClaudeMd: true` strips it); git status snapshot; preloaded `skills:` (first 32). "Because the subagent doesn't see your CLAUDE.md, a rule that must apply should be restated". Relevance for catherd: headless `claude -p` workers pay for CLAUDE.md/MEMORY.md on every lane, a hidden brief-bloat source (this repo's own global CLAUDE.md plus memory index is several KB).
- **Frontmatter per role:** `model`, `effort` (`low..max`), `tools`/`disallowedTools`, `maxTurns` (output marked partial, resumable), `isolation: worktree` (auto-cleaned if unchanged), `memory`, scoped `hooks`. Model resolution: per-call param, then definition, then `CLAUDE_CODE_SUBAGENT_MODEL`, then parent; `..._FORCE=1` pins everything.
- **Agent teams:** shared task list, dependency-blocked tasks, claiming via file lock, mailboxes. Quality gates via hooks: `TaskCompleted` and `TeammateIdle` exit code 2 "prevents completion and sends feedback" (https://code.claude.com/docs/en/agent-teams#enforce-quality-gates-with-hooks). Guidance: "Two teammates editing the same file leads to overwrites. Break the work so each teammate owns a different set of files"; 5-6 tasks per teammate; start with 3-5 teammates. Experimental, no nested teams, no resume of in-process teammates.
- **Steal:** a `TaskCompleted`-style gate that rejects completion unless the daemon-run checks passed (we already have the daemon; the lesson is making "done" a refusable event); `omitClaudeMd`-style minimal context for narrow roles; file ownership as the parallelism contract.

## 9. BMAD-METHOD code-review skill
- Repo: https://github.com/bmad-code-org/BMAD-METHOD , 54.6k stars, pushed 2026-10-20. Path `skills/bmad-code-review/` (https://github.com/bmad-code-org/BMAD-METHOD/tree/main/skills/bmad-code-review).
- **Review design:** a step-file workflow (gather context, review, triage, route, present). Step 2 runs several narrow "lenses" as parallel blocking subagents, each with a `Run only when` condition (skipped lenses are announced), same model capability as the session; a failed or empty lens is recorded in `failed_layers` rather than aborting. Lens prompts are tiny and single-purpose.
- **`review-prompts/verification-gap.md`:** finds behaviour changed "that could break later without any test failing". Explicit definition of a test that does NOT count: "assertions on source text; success, no-throw, or snapshot-only checks; mock or log-call checks; manual checks; tests that mock away the integration; ... stale assertions". Evidence rules: read a test before saying what it covers; search before saying none exists; "Drop any finding you cannot ground." No severity ranking. Gap kinds: regression, missing-adoption, broken-verification (skipped/flaky/weak test), stale-verification.
- **`references/claims-check.md`:** the change's own narrative (commit message, description) "is the author's testimony, not evidence"; the reviewer reads it LAST, after tracing, so it cannot steer the trace, then tries to falsify each checkable claim.
- **Steal:** claims file read last; the "what counts as a test" list in the verifier prompt; lenses with run-conditions; ungrounded-finding drop rule (shallow reviewers are fixed by grounding rules more than by bigger models).

## 10. Goose recipes and subagents
- Repo: https://github.com/aaif-goose/goose , 55.7k stars, pushed 2026-10-26.
- Subagents: independent instances, can run their own provider and model, can be restricted to one extension; 5-minute default timeout; "if any subagent fails, you get results only from the successful ones" (https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/subagents.mdx).
- Recipes `retry` block (https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/recipes/recipe-reference.md): `max_retries`, `checks: [{type: shell, command}]` (exit 0 = pass), `timeout_seconds`, `on_failure` command; on failed check it runs on_failure, resets the agent's message history to initial state and restarts. Small and deterministic; the same "runtime runs the check" idea as claw, but retry restarts clean rather than continuing.
- Steal (minor): `on_failure` cleanup command between attempts (reset DB/ports/containers) to cut environment flake carry-over.

## Ranked: top 10 ideas for catherd

1. **Daemon-run, agent-unwritable acceptance checks decide "done"** (claw-orchestrator; echoed by fable-advisor "re-run the verification command", goose retry checks). Plan items declare `command` checks (argv, exit code, timeout, process-group kill); the daemon executes them and records an evidence bundle (verdict, per-check log tail, diff). Verifier models only judge what a command cannot. Fixes: verifiers that pass without running tests.
2. **Protected-test hash check before the gate** (claw-orchestrator). Hash all test files/configs/test scripts at lane start, compare bytes before the checks, refuse if changed unless the plan allows it. Fixes: shallow verification via weakened tests.
3. **`failure_class: product | harness` in the verdict, with a free harness-repair dispatch and a failure-signature stop rule** (oh-my-openagent `ulw-execute` SKILL). Signature = failing check + first error line with temp paths, timestamps, pids, durations stripped; stop on repeat of same signature on consecutive attempts, 3rd failure, or a wall-clock bound; harness failures do not consume a fix round. Fixes: review rounds wasted on environment flakiness.
4. **File-handoff briefs: task-only brief file + report file, 5-line return contract** (superpowers). The brief extracts only that lane's task text; shared decisions go to an append-only notes file the worker reads on demand (oh-my-openagent notepads); no pasted history ("42k chars of which 99% was pasted history"); worker writes its long report to disk. Fixes: 100-145 KB briefs.
5. **Strip ambient context from narrow roles** (Claude Code `omitClaudeMd`, `skills` only if listed; AO splits short task prompt from standing system prompt and fails spawn if the rules file is missing). Audit what each vendor CLI auto-loads (CLAUDE.md, memory index, AGENTS.md) per role and turn it off for reviewers/cheap workers. Fixes: bloated briefs, wrong duties.
