## 0. Headline findings for catherd

1. **"astra" is GPT-6 Astra, `gpt-6-astra`.** It is OpenAI's top model, released 2026-09-03, and Codex supports it (`codex -m gpt-6-astra`). **"fable" is Claude Fable 5.1, `claude-fable-5-1`**, released 2026-09-01, Claude Code alias `fable`. **"sonnet" is Claude Sonnet 5, `claude-sonnet-5`**, released 2026-06-30, alias `sonnet`.
2. **The current catalog is wrong in several places:**
   - `claude-opus-5-5` supports `low, medium, high, xhigh, max`, not only `low, medium, high`. Its API default is `medium`.
   - In Codex, `gpt-6-sol` supports `low, medium, high, xhigh, max, ultra`, not stopping at `xhigh`.
   - The Codex harness gives GPT models a **272,000-token context window by default** (`max_context_window` 872,000). It is not 400,000. The raw API model has 1,050,000.
   - `imageOut: true` on the GPT models really describes the Codex built-in image-generation tool (`$imagegen`, gpt-image-2), not the model's own output modality, which is text only. The tool is officially documented for ChatGPT sign-in.
3. **The spec's premise is out of date.** Spec §5 says models.dev does not list the Codex ids. models.dev now lists `openai/gpt-6-sol`, `gpt-6-luna`, `gpt-6-astra` and all current Claude ids. However, models.dev describes the **API** view (efforts include `none` and exclude `ultra`; context is 1.05M), while Codex has its own catalog. The authoritative source for the Codex backend is **`codex debug models`**, which prints JSON non-interactively.
4. **Where the seed scores come from:**
   - `honesty` for Sol (95.1) and Luna (71.3) is exactly 100 minus the "Broken Search Tool" failure rate in the GPT-6 system card appendix (4.92% and 28.67%). **Confirmed.**
   - `repo_code` for `sol#medium/high/xhigh` (56.6/65.3/66.6) matches the per-effort DeepSWE v1.1 figures from OpenAI's Sol/Luna launch, as reproduced by Kingy AI. The OpenAI page itself returns 403 to fetchers, so this is **secondary-confirmed**.
   - `luna#high` = 59.3: **UNVERIFIED**. No per-effort Luna figure was found; only Luna max = 66.6 is published.
   - The `terminal` values for Sol/Luna (4.5/18.7/26.3/30.3): **UNVERIFIED**. The only published Sol/Luna terminal numbers are Terminal-Bench **4.0** at max effort (Sol 43%, Luna 13%, from Artificial Analysis).
   - `claude-opus-5-5` terminal low/medium/high = 31.3/52.5/56.6: **UNVERIFIED and probably mis-sourced.** The Opus 5.5 system card gives Terminal-Bench 4.0 at xhigh = 66.4 and at max = 64.8. The value **52.5 at medium equals Opus 5.5's CursorBench 4.0 medium score**, which suggests the seed mixed benchmarks.
   - `secs_per_task`: **no primary source found** for any model. DeepSWE publishes cost, output tokens and steps, not seconds.
5. **Benchmark versions moved on.** Terminal-Bench 2.x is saturated (the top score on 2.1 is 91.4%), and vendors now report **Terminal-Bench 4.0**. For repo work, vendors report **DeepSWE v1.1**, SWE-bench Pro and FrontierCode. The catalog should record the benchmark name and version with each score.

### 1.2 Claude Code specifics

- **Subagent frontmatter `model:`** accepts `sonnet`, `opus`, `haiku`, `fable`, a full model id such as `claude-opus-5-5` or `claude-sonnet-5`, or `inherit`. Source: https://code.claude.com/docs/en/sub-agents
  - Resolution order: the per-invocation `model` parameter, then the frontmatter `model`, then the `CLAUDE_CODE_SUBAGENT_MODEL` env var, then the main conversation's model.
  - Gotcha: when the main session is on the same family as the alias, the subagent runs on the main session's **exact** model, including its `[1m]` suffix. **catherd should write full ids, not aliases, to pin a rung.**
- **Subagent frontmatter `effort:`** accepts `low`, `medium`, `high`, `xhigh`, `max`. It overrides the session effort; the default is to inherit. "Available levels depend on the model", so Haiku 4.5 has none. Same source.
- **CLI flags:**
  - `claude --model <alias|id>` and `claude --effort <low|medium|high|xhigh|max>` (confirmed from `claude --help` on v2.1.282).
  - Effort can also be set with the `CLAUDE_CODE_EFFORT_LEVEL` env var, or in settings with `effortLevel` or per-model `modelSettings.<id>.effort`.
- **More aliases:** `opus[1m]`, `sonnet[1m]`, `opusplan`, `best`, `default`.
- **Alias resolution by provider:**
  - Anthropic API: opus = Opus 5.5, sonnet = Sonnet 5.
  - Claude Platform on AWS: sonnet = Sonnet 4.6.
  - Bedrock / Google Cloud: sonnet = Sonnet 4.5.
  - Microsoft Foundry: opus = Opus 4.6, sonnet = Sonnet 4.5.

  This is another reason to store full ids.
- **Fable requirements:** Claude Code ≥ 2.1.255 for Fable 5.1 (Help Center). The model-config page says 2.1.257+ (**minor discrepancy**). If safety classifiers flag a request, Fable falls back to other models (biology to Opus 5, cyber to Opus 4.8).
- **Listing models non-interactively:** Claude Code has **no** `models` subcommand (checked with `claude --help`, v2.1.282). Options:
  - With an API key: the Models API `GET /v1/models` (https://platform.claude.com/docs/en/api/models/list) returns `max_input_tokens`, `max_tokens` and a `capabilities` object.
  - With a subscription login: use a static list plus the docs.

### 1.3 Subscription quota (how a Claude plan "prices" each model)

- **Fable 5/5.1** (Help Center, https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan):
  - **Pro and Team Standard:** not included in plan limits; **usage credits only**, which is metered.
  - **Max, Team Premium and Enterprise premium seats:** included, but capped at **up to 50% of weekly limits**.
  - **API and usage-based Enterprise:** API rates.
- **Opus 5.5, Sonnet 5 and Haiku 4.5** draw from the normal plan limits. Anthropic publishes **no per-model quota multipliers** (**UNVERIFIED gap**). The reasonable proxy is API price ratios: Haiku 1 : Sonnet 2 : Opus 5.5 4 : Fable 10 (input), with the same ratios for output.

Notes:
- **`ultra` is a Codex-harness effort.** The catalog describes it as "Maximum reasoning with automatic task delegation": it spawns parallel subagents. Treat `ultra` as a distinct rung with its own cost and time, not as a deeper `max`.
- **`none` is API-only.** The Codex catalog does not list it.

### 2.3 Built-in image generation (the artist role)

- Codex feature `image_generation` is **stable, on by default** (`codex features list`, 0.157.0). You invoke it with `$imagegen` or implicitly.
- It "uses `gpt-image-2` and counts toward your general Codex usage limits", and "image generations use included limits 3–5× faster" than text turns (https://learn.chatgpt.com/docs/image-generation).
- **Documented for ChatGPT sign-in.** For API pricing, the docs suggest setting `OPENAI_API_KEY` and generating through the Images API.
- Third-party writeups say the built-in tool does not work with API-key login (https://codex.danielvaughan.com/2026/04/27/codex-cli-image-generation-gpt-image-2-visual-development-workflows/). **UNVERIFIED from OpenAI**, but the API model pages list `image_generation` as a Responses API tool for gpt-6-sol/luna/astra.
- **Recommendation:** model this as a backend/auth capability (`imageGenTool: chatgpt-login`), not as the model's `imageOut`.
- Current API image models: `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare`, `gpt-image-2` (https://developers.openai.com/api/docs/models).

### 3.3 honesty (tool-failure disclosure)

**OpenAI "Broken Search Tool" eval.** The model gets a task that needs search while search is unavailable; the eval measures how often its final message fails to say so. Run at max effort. Sources: GPT-6 Astra system card appendix "Sol and Luna" §11.6.4.2, Figure 65, dated 2026-09-22 (https://deploymentsafety.openai.com/gpt-6-astra/sec:appendix-sol-luna); figure image `…/assets/images/appendix/09-broken-search-tool.png`.

| Model | Failure rate | → honesty (100 − rate) |
|---|---|---|
| gpt-6-astra | 1.50% | 98.5 |
| gpt-6-sol | 4.92% | **95.1** (matches catalog) |
| gpt-6-luna | 28.67% | **71.3** (matches catalog) |
| gpt-5.6-sol | 77.46% | 22.5 |
| gpt-5.6-luna | 78.25% | 21.8 |

Coding deception from the same appendix (Figure 64), lower is better: Astra 0.51%, Sol 1.30%, GPT-5.6 Sol 10.41%, Luna 2.81%, GPT-5.6 Luna 9.54%.

**Anthropic has no equivalent broken-tool metric.**
- The Opus 5.5 system card §6.5.4.4 reports a *spontaneous disclosure rate* of concealed git manipulations: Opus 5.5 at 96.9%, higher is better. It is a different eval and **not comparable**.
- The card also notes more "asserting unverified inferences as fact" in internal use (Zvi summary: https://thezvi.wordpress.com/2026/09/23/claude-opus-5-5-the-system-card/).
- Fable 5.1 system card (https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card): not examined, **gap**.
- Sonnet 5 and Haiku 4.5: **gap**.

**Recommendation:** store `honesty` with an `eval` field and never compare honesty across vendors unless the eval ids match.

### 4.1 Split the catalog into three layers, all data and no code

1. **Models, discovered.** Where they come from:
   - **Codex:** `codex debug models` gives the account's live list. Fall back to `codex debug models --bundled` when logged out. Take `slug`, `supported_reasoning_levels[].effort`, `context_window`, `max_context_window`, `input_modalities`, `visibility`, `upgrade`/`retirement_at` and `supported_in_api`. Keep `visibility: "list"` entries and drop hidden and specialty ones (`model_specialty`), unless the user allowlists them.
   - **Claude:** a shipped static list. There is no CLI listing, and `GET /v1/models` works only with an API key. When a key is present, use the Models API to refresh.
   - **models.dev:** only for opencode providers, and as a cross-check of API-level context and effort values.
   - Store the result as a snapshot with `fetchedAt` and `source` (`codex-cli@0.157.0`, `anthropic-docs@2026-09-25`), like the current `models-dev.json`. `catherd catalog refresh` should update all three.
2. **Harness facts, shipped data** (`catalog/backends.json`): per-backend knowledge the CLIs do not expose.
   - Claude: effort values, frontmatter/flag mapping, full-id vs alias rules, the Haiku no-effort rule.
   - Codex: `ultra` means multi-agent, `none` is excluded, image-gen needs ChatGPT login.
   - Plan-quota tables (§1.3, §2.4).

   This lets a new model with a known family inherit behavior without code changes.
3. **Scores, versioned and sourced** (`catalog/scores.json`). One record per `(rung, dimension)`:
   ```json
   {"rung":"gpt-6-sol#high","dim":"repo_code","value":65.3,
    "eval":"deepswe-1.1","harness":"codex","source":"https://…","published":"2026-09-22",
    "confidence":"secondary"}
   ```
   - Bars must name the eval (`repo_code` means `deepswe-1.1`, `terminal` means `terminal-bench-4.0`), so that a benchmark version change does not silently mix scales.
   - Keep `honesty` eval-scoped (`openai-broken-search-tool`).
   - Add a `measured` source type fed from catherd's own run history, for `secs_per_task` and, later, success rates.

### 4.2 Unscored models ("treat like")

- Keep the rule that the router never places an unscored rung. Add **shipped default `treatLike`** rules in data, keyed by family, and mark each as `inferred`. For example:
  - `gpt-6-sol#max` treated like `gpt-6-sol#xhigh`, with a time penalty.
  - `claude-sonnet-5#high` treated like a documented anchor: Anthropic says "Sonnet 5 medium ≈ Sonnet 4.6 high", on the effort page.
  - `gpt-6-luna#medium` treated like `gpt-6-luna#high` minus one rung.

  The TUI should show inferred scores differently, and the user can confirm or override them in `catalog.override.json`.
- New ids that appear in discovery but have no scores and no family rule are **listed but disabled**. The TUI prompts once for "treat like".
- Model upgrades: use Codex's `upgrade.model` field to carry a user's enabled rungs forward automatically, for example from `gpt-5.6-sol` to `gpt-6-sol`. Warn on `retirement_at`.

### 4.3 Cost ranking: subscription vs metered

- Replace the hand-written integer `costRank` with a computed rank from a per-rung `cost` record, evaluated against the user's **billing mode per backend**, set in the profile:
  - **Subscription (ChatGPT plan):** cost unit = the fraction of the 5-hour allowance one task uses. Use the official Codex table (§2.4) as relative weights: Luna 1, Sol ≈ 20, Astra ≈ 60 on Plus midpoints. Multiply by an effort factor derived from tokens per task. Add ×2.5 for fast mode, a multi-agent factor for `ultra`, and ×3–5 for image-generation turns.
  - **Subscription (Claude plan):** weight by API price ratio as a proxy. Haiku 1, Sonnet 2, Opus 5.5 4, Fable 10; the per-model quota multipliers are UNVERIFIED. **On Pro or Team Standard, Fable is metered (usage credits) and should be ranked as metered.** On Max, Fable is included but capped at 50% of weekly usage; model that as a soft cap.
  - **Metered (API key, OpenRouter, Claude usage credits):** cost unit = USD per task. Estimate it as price × (typical input, cached and output tokens per task at that effort). Seed the token counts from published per-task costs (DeepSWE, CursorBench, OpenAI launch) and replace them with measured `runs.jsonl` token counts.
- Keep "subscription before metered at similar strength" as a tie-break policy, not a baked-in integer. This lets a user with only an API key get a sensible order automatically.
