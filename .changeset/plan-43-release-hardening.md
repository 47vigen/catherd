Release hardening for unattended runs. `catherd profile set land.autoMerge true` (off by default; pinned when a run starts) makes a base run merge each landed milestone into the base itself, with a `--no-ff` merge commit `chore: merge <run> <milestone> <title>` pushed without force; any git failure falls back to the push question. A plan line `Format: <command>` formats each milestone's staged owned files before its commit, and a pre-commit hook refusal becomes a fix round. A land or verifier park answered with a fix starts a fix round; `retry` runs it again and `accept` waives it. A resumed claude-code dispatch records its own cost, not its thread's running total. A passing test line no longer reads as a failure, a reply with no `STATUS:` line is asked again once, a `check_broken` stop parks at once, a lane whose rung left the profile is routed again, and the daemon waits for free disk instead of stopping for good on a full disk. Two milestones that land together both merge (a push that lost the race merges again on the new base), and a failed auto-merge shows under the panel's landing filter and Setup's Land tile. A proxy, network or overloaded-server error retries the lane's own rung with a backoff instead of climbing it, and parks after 30 minutes. A verifier reply with no `VERDICT:` line is asked for it once, and a judge that dismisses every finding of a verifier FAIL lands that commit.
